### 学んだこと

**技術的な学び**:
- **「クリックを飲む」には `click` のキャプチャフェーズが要る**。React 18 は root コンテナで bubble を listen する
  ため、`document` のキャプチャで `stopPropagation()` すれば合成イベントに届かない。`mousedown` を止めても
  後続の `click` は別途発火するので、飲む目的なら `click` 1本のほうが状態を持たずに済む。
- **「閉じる」処理をコンポーネント内に閉じ込めきれないケースがある**。閉じた後にフォーカスをどこへ渡すかは
  「何を押して閉じたか」に依存し、それは編集コンポーネントの知識ではない。**確定（内部の関心事）と
  閉じ方（外部の関心事）を分ける**と、フォーカスの二重遷移のような症状が構造的に消える。最初からこの分割で
  設計できていれば検証の指摘を待たずに済んだ。
- **UI ライブラリの既定値は「意図した設計」ではない**。Tailwind v3 preflight の `button { cursor: pointer }` に
  よって、押しても何も起きない行まで指カーソルになっていた。フレームワーク由来の見た目は、機能を変えたときに
  一緒に見直す対象になる（機能とアフォーダンスの不一致は、コードを読んでいるだけでは気づきにくい）。
- **1つの決定が、直接は語られていない操作に波及する**。「右ペインの1クリック目は飲む」を決めた結果、
  別名エリアクリックでの対象切り替えが2クリックになった。決定事項を書くときは「この決定が既存のどの操作に
  影響するか」を洗い出す欄があってもよかった。

**プロセス上の改善点**:
- 計画承認ゲートで「追加で決めた細部」を明示したことで、ユーザーが**別名チップ領域の存置**（前単位）や
  **カーソルの不一致**（本単位）を指摘でき、実装前に軌道修正できた。提案を黙って実装せず、根拠付きで
  俎上に載せる形式は機能している。
- 受け入れ提示に「挙動の変化」を独立した見出しで書いたのは有効だった（2クリック化は AC には現れないが、
  ユーザーが最も体感する差分だった）。

### 次回への改善提案
- **要件の「決定事項」表に、その決定が波及する既存操作を併記する欄を設ける**。今回の2クリック化のように、
  AC には現れないが体感に効く変化を、計画段階で洗い出せる。
- コンポーネントに命令ハンドルを生やすときは、**「実行」と「後始末（フォーカス・モード遷移）」を分けられないか**を
  最初に検討する。分けられるなら分けたほうが、呼び出し側の文脈差を吸収できる。
- フレームワークの preflight / 既定スタイルに由来する見た目（カーソル・アウトライン・タップハイライト）は、
  インタラクションを変更する単位のチェックリストに入れておく。
