# 要求内容 — alias-editor-close（別名編集の終了導線）

## 概要

別名チップ編集（`AliasEditor`・デザイン状態1e）を閉じる手段が**キーボードのみ**で、マウスだけでは終われない状態を解消する。**右ペインの編集行の外を押したら閉じる**（その1クリックはクリック先の操作を実行しない）、**左ペイン・ヘッダーを押したら操作を実行しつつ閉じる**、そして**可視な [完了] ボタン**を追加する。閉じる際は入力途中の文字を別名として確定する。

## 背景

現在、別名編集を閉じる経路は次のとおりで、**マウスだけで完結する手段が1つも無い**。

| 経路 | 現状 |
|---|---|
| `Escape` | 閉じる（入力途中の文字は破棄） |
| `Enter`（入力が空のとき） | 閉じる |
| 別の行の別名エリアをクリック | 対象が移る（＝実質的に閉じる） |
| 検索条件が変わって対象行が結果から消えた | 自動で閉じる（`Popup` の防御 effect） |
| **背景・他の行・左ペイン・ヘッダーのクリック** | **閉じない**（編集が開いたまま残る） |

インライン編集（タイトル/URL・状態1d）には [キャンセル] / [保存] ボタンがあり、押せば必ず終われる。**別名編集にだけ可視な終了手段が無い**という非対称が、「どうやって終わるのか分からない」「使いづらい」という体験の直接の原因になっている。

さらに、編集中に他の行をクリックすると**そのブックマークが開いてポップアップごと閉じる**。編集していた文脈が失われるうえ、別名編集は5秒アンドゥのようなやり直し手段を持たないため、この誤操作のコストは大きい。

## 決定事項（本要求の作成時にユーザーと確定）

| # | 論点 | 決定 |
|---|---|---|
| 1 | 外側クリックで閉じる範囲 | **右ペイン**の編集行の外を押したら閉じる。**その1クリックはクリック先の操作を実行しない**（1回目は閉じるだけ） |
| 2 | 左ペインの扱い | 左ペインは**押下可能なまま**（スコープ変更等は通常どおり実行される）。そのうえで**別名編集は解除する** |
| 3 | 入力途中の文字 | **別名として確定してから**閉じる（打ちかけの語を失わない） |
| 4 | 可視な終了導線 | **[完了] ボタンを置く** |
| 5 | 編集中の他の行のカーソル | 別名編集中、**編集行以外の結果行では指（ポインタ）カーソルにしない**。押せないのに押せるように見える状態を消す |

## 実装対象の機能

### 1. 右ペインでの外側クリック（決定事項1）

- 別名編集中に、**編集行以外の右ペイン領域**（他の結果行・メタ行・空白）を押したら編集を閉じる。
- **その1クリックはクリック先の操作を実行しない**。他の行を押しても**ブックマークは開かない**。もう一度押せば通常どおり開く。
  - 理由: 編集中の誤クリックでポップアップが閉じ、編集文脈を失う事故を構造的に防ぐ。`selection-mode` 以降、本プロダクトは一貫して「押す場所によって取り返しのつかない結果にならない」方向で設計している。
- 編集行の内部（チップ・`✕`・入力欄・ヒント行）を押しても閉じない。

### 2. 左ペイン・ヘッダーでの操作（決定事項2）

- **左ペイン**（フォルダツリー）を押したら、スコープ変更・展開トグル等の操作は**通常どおり実行**し、あわせて別名編集を閉じる。
- **ヘッダー**（検索ボックス・「☑ 選択」・「＋ 追加」）も同じ扱いにする。検索ボックスをクリックしてすぐ入力できないのは不自然であり、左ペインと挙動を分ける理由が無いため。
  - ※ 決定事項2 は左ペインについての指示だが、同じ理屈がヘッダーにも当てはまるため同一の扱いとする（本要求で明示する）。
- 右ペイン以外は「クリックを飲む」対象にしない（＝1回のクリックで操作が完了する）。

### 3. 入力途中の文字の確定（決定事項3）

- 閉じる際、入力欄に残っている文字は**別名として確定してから**閉じる（`commitAlias` の通常経路を通す。重複・空・上限の判定も同じ）。
  - 対象: 外側クリック（右ペイン/左ペイン/ヘッダー）・[完了] ボタン。
- **`Escape` は従来どおり破棄**とする。「取りやめるなら `Escape`」という使い分けを明確にし、明示的な取り消し手段を残す。
- 空入力での `Enter` は従来どおり（確定対象が無いのでそのまま閉じる）。

### 4. 編集中の他の行のカーソル（決定事項5）

- 別名編集中、**編集行以外の結果行**にカーソルを乗せても**指（ポインタ）カーソルにしない**（既定の矢印カーソルにする）。
- 原因は Tailwind v3 の preflight が `button { cursor: pointer }` を当てていること。結果行は `<button>` のため、押しても「閉じるだけ」の状態でも押下可能に見えてしまう。**決定事項1で「1回目のクリックは飲む」と決めた以上、見た目もそれに合わせる必要がある**（機能とアフォーダンスの不一致を残さない）。
- 左ペイン・ヘッダーは**指カーソルのまま**にする。こちらは1クリックで実際に操作が実行されるため（決定事項2）、押せる見た目が正しい。
- 対象は**別名編集中のみ**。インライン編集（状態1d）中の他行は本単位では扱わない（クリックすると実際にブックマークが開くため、指カーソルのままが実態と合っている）。

### 5. [完了] ボタン（決定事項4）

- 別名編集の枠内に、押せば必ず終われる [完了] ボタンを置く。
- 押下で「入力途中の文字を確定 → 閉じる」を行う（外側クリックと同じ経路）。
- 配置はヒント行（「Enter で確定 / Backspace で直前のチップを削除」と `N / 20` の行）の右端とする。チップ入力ボックスの内側は、別名が増えると内部スクロールで流れてしまい常に見える位置に置けないため。

## 受け入れ基準

- [ ] **AC-1（右ペインの外側クリックで閉じる）**: 別名編集中に他の結果行・メタ行・右ペインの空白を押すと編集が閉じる。
- [ ] **AC-2（1回目はクリックを飲む）**: AC-1 のクリックでは**ブックマークが開かない**（ポップアップが閉じない）。同じ行をもう一度押すと通常どおり開く。
- [ ] **AC-3（左ペイン）**: 別名編集中に左ペインのフォルダを押すと、**スコープが切り替わり**、かつ別名編集が閉じる（1クリックで両方が起きる）。
- [ ] **AC-4（ヘッダー）**: 別名編集中に検索ボックスを押すと、編集が閉じてそのまま入力できる。「＋ 追加」「☑ 選択」も1クリックで機能する。
- [ ] **AC-5（編集行の内部は閉じない）**: チップ本体・`✕`・入力欄・ヒント行を押しても編集は閉じない（従来どおりの編集操作が続く）。
- [ ] **AC-6（入力途中の確定）**: 「こうし」と入力した状態で外側クリック / [完了] を行うと、`こうし` が別名として保存されてから閉じる。
- [ ] **AC-7（Escape は破棄）**: 同じ状態で `Escape` を押すと `こうし` は保存されずに閉じる。
- [ ] **AC-7b（他の行のカーソル）**: 別名編集中、編集行以外の結果行にカーソルを乗せても指カーソルにならない。左ペインのフォルダ・ヘッダーのボタンは従来どおり指カーソルになる。
- [ ] **AC-8（[完了] ボタン）**: 別名編集中に [完了] が見えており、押すと（入力途中の文字を確定して）閉じる。
- [ ] **AC-9（既存の終了経路の非退行）**: `Escape` / 空入力の `Enter` / 別の行の別名エリアクリック / 対象行の消失、いずれも従来どおり閉じる。
- [ ] **AC-10（他モードへの非影響）**: インライン編集・フォルダ選択パネル・現在ページ登録パネル・右クリックメニュー・選択モードの挙動が変わらない。
- [ ] **AC-11（品質ゲート）**: `pnpm test` / `pnpm lint` / `pnpm type-check` が通る。外側クリックの判定（どこを押したときに「閉じる」「クリックを飲む」か）に純粋関数とユニットテストがある。

## 成功指標

- マウスだけで別名編集を開始・編集・終了できる（現在は終了だけキーボード必須）。
- 別名編集中の誤クリックで、サイトが開いてポップアップが閉じる（＝編集文脈を失う）経路が無くなる。
- 「押せるように見えるのに押しても何も起きない（閉じるだけ）」という見た目と挙動のズレが無くなる。

## スコープ外

- **インライン編集（状態1d）の終了導線**。[キャンセル] / [保存] ボタンが既にあり、マウスだけで終われるため本単位では触らない。
- 別名編集の**アンドゥ**（削除した別名を戻す手段）。既存どおり無し。
- チップ入力のキー割り当て変更（`Enter` / `,` / `Space` / `Backspace` は現状のまま）。
- ポップアップ外（ブラウザ側）のクリックでポップアップ自体が閉じる挙動（Chrome の仕様であり変更できない）。
