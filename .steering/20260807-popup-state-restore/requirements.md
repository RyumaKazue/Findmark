# 要求内容

- **作業単位**: U19 / popup-state-restore
- **対応MVP機能**: 機能13「ポップアップ状態の復元」(P1)
- **依存**: U8a (focus-three-state) / U11 (folder-scope-tree) — いずれも ✅ 完了

## 概要

ポップアップを閉じた時点の UI 状態(フォーカス位置・フォルダスコープ・選択中ブックマーク・検索クエリ)を `chrome.storage.local` に**変更のたびに即時(debounce 付き)** 保存し、次回起動時に復元する。これにより、同じ作業を繰り返すユーザーが毎回操作をやり直さずに前回の続きから再開できる。

## 背景

ポップアップは外側クリックで唐突に閉じるため、「閉じる直前の一括保存」には依存できない。前回どこを見ていたか(スコープ・選択行・クエリ・フォーカス)を引き継げないと、繰り返し作業のたびに絞り込み直す必要があり、中核価値「数秒で引ける検索」を損なう。端末固有の状態のため `storage.sync` ではなく `storage.local` に保存する。(PRD 機能13 / functional-design「State Management」)

## 実装対象の機能

### 1. セッション状態の保存(即時・debounce 付き)

- 4項目 `focusArea` / `scopeFolderId` / `selectedBookmarkId` / `query` を `storage.local` の `LocalState.session`(`PopupSession`)へ保存する。
- 変更のたびに debounce 付きで即時保存し、閉じる直前の一括保存に依存しない。
- 選択中ブックマークは**インデックスではなくブックマーク ID** で保存する。

### 2. セッション状態の復元(索引構築後に適用)

- 次回起動時、保存された `PopupSession` を読み込み、既定値を先に適用したうえで読み込み完了後に上書きする。
- 復元の適用は**検索索引の構築完了後**に行う(選択行の ID 解決に検索結果が必要)。
- 保存先が見つからない項目のみ既定値へフォールバックする(スコープ→「すべて」/ 選択行→先頭行)。`focusArea` は影響を受けず保存値のまま復元する。

### 3. 復元クエリ復帰時の全選択

- 復元されたクエリが残った状態で、左/右ペインから印字文字を打って検索ボックスへ復帰したとき、既存クエリを**全選択状態**にして次の入力で置き換わるようにする。

## 受け入れ条件

> 出典: PRD「13. ポップアップ状態の復元」/ functional-design「State Management(`PopupSession`)」「復元時のフォールバック」「起動時の先読み」。

### 保存

- [ ] AC-1: 4項目(フォーカス位置 / フォルダスコープ(フォルダ ID) / 選択中ブックマーク / 検索クエリ)を `chrome.storage.local`(端末固有)に保存する。
- [ ] AC-2: 選択中のブックマークは**インデックスではなくブックマーク ID** で保存する(増減・結果変化でズレないため)。
- [ ] AC-3: 保存は**変更のたびに即時(debounce 付き)** 行い、閉じる直前の一括保存に依存しない。

### 復元(既定値とフォールバック)

- [ ] AC-4: 保存された状態がない初回起動時は、フォーカス位置=**左ペイン(フォルダツリー)** / スコープ=**「すべて」** / 選択行=**先頭行** / クエリ=**空** とする。
- [ ] AC-5: 保存されたフォルダが存在しない → スコープを「すべて」へフォールバックする。
- [ ] AC-6: 保存されたブックマークが存在しない → 選択行を先頭行へフォールバックする。
- [ ] AC-7: 上記フォールバック時も**フォーカス位置は影響を受けず、保存値のまま復元**する。
- [ ] AC-8: 選択行が**ID で保持**され、インデックスのズレが起きない(結果件数が変わっても保存 ID の行が選択される)。

### 適用タイミング / 復帰

- [ ] AC-9: 保存されたクエリで結果が0件になる場合もそのまま表示する(`Escape` の段階戻りで1段ずつ解除できる)。
- [ ] AC-10: フォーカス位置・スコープ・クエリの復元は**セッション/フォルダツリー読み込み完了時点で即適用**し、既定状態のフラッシュを避ける(索引構築の完了を待たない)。選択行の ID→インデックス解決だけは**検索索引の構築完了後**に行う(選択行の解決に検索結果が必要なため)。既定値は先に当たっているため 200ms 要件を満たす。
- [ ] AC-11: 復元されたクエリが残った状態で印字文字を打って検索ボックスへ復帰したとき、**既存クエリが全選択**され次の入力で置き換わる(継続絞り込みは `→` / `End` でキャレットを末尾へ送れる)。

### 品質ゲート

- [ ] AC-12: `pnpm test` / `pnpm lint` / `pnpm type-check` がすべてパスする。純粋ロジック(既定値・フォールバック解決・セッション導出)にユニットテストがある。

## 成功指標

- 起動→キー操作受付までの既定フォーカス適用が 200ms 以内(既定値を先に適用)。
- 復元により、前回のスコープ・選択・クエリ・フォーカスが再現される。

## スコープ外

以下はこのフェーズでは実装しない:

- 展開状態(`expandedFolderIds`)の保存・復元 — 既に U11 で `LocalState` に永続化済み。本単位では触らない。
- 複数選択(U13)・現在ページ登録(U14)等、他モードの状態保存。
- `storage.sync` によるクロスデバイス同期(本機能は端末固有 = local が正)。
