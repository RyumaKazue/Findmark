## 2. 背景（何を解決するか）

U11 が起動直後の既定モードを `LIST` → `FOLDER_TREE` に変更した際、`Popup.tsx` の
`if (currentMode === 'LIST') { ... }` の**内側に置かれたままだったショートカット**が左ペインで一切効かなくなった。
前単位でこのうち `Ctrl/Cmd+D`（現在ページ登録）と `Ctrl/Cmd+M`（一括移動）を修正したが、
全件監査（前単位フェーズ11）で見つかった残り2件は「破壊的操作を独断で有効化しない」判断から未対応のまま残している。

さらに構造上の問題として、**これらの有効条件は `Popup.tsx` の `useEffect` 内に直書きされており、
プロジェクト方針（純粋ロジックのみテストし React コンポーネントのテストは持たない）では検証できない**。
実際、前単位の3ラウンドの手戻りはいずれも `pnpm test` / `lint` / `type-check` と `implementation-validator` を
すべて通り抜け、実機確認でしか検出できなかった。

## 3. 実装対象

### 3.1 バグ修正1: `Delete`（一括削除）が FOLDER_TREE で効かない

- **現状**: `Popup.tsx` の `shortcutIntent === 'delete' && listFocus === 'result'` が LIST ブランチ内にあり、
  FOLDER_TREE では単一削除・一括削除の**どちらも**効かない。
- **一括操作バーの「削除」ボタンはモード遷移を伴わないため FOLDER_TREE でも動作する**ため、
  ボタンとキーで挙動が食い違っている。
- **修正方針**: 「チェック選択がある場合の `Delete`（＝一括削除）」のみを FOLDER_TREE でも有効にする。
  単一削除（対象＝右ペインでフォーカス中の行）は従来どおり `LIST` + `listFocus === 'result'` 限定のままとする。

### 3.2 バグ修正2: `Ctrl/Cmd+A`（全件選択）が FOLDER_TREE で効かない

- **現状**: `shortcutIntent === 'select-all' && listFocus !== 'search'` が LIST ブランチ内にあり、FOLDER_TREE で効かない。
- 横取りしないため、ブラウザ既定の「ページ内テキスト全選択」が発動する（ポップアップの文字列が選択される）。
- **修正方針**: 対象が「表示結果の全件」でフォーカス位置に依存しないため、FOLDER_TREE でも有効にする。
  検索ボックスにキャレットがある間（`LIST` + `listFocus === 'search'`）は従来どおり素通しし、ネイティブのテキスト全選択を温存する。

### 3.3 再発防止: 有効条件を純粋関数へ切り出す

- `modeMachine.ts` に `isShortcutEnabled(intent, ctx)` を新設し、7つのショートカットすべての有効条件を集約する。
- `Popup.tsx` の各 `if` は「インテント一致 + `isShortcutEnabled`」の形に統一し、条件式の直書きをやめる。
- これにより「モード × フォーカス位置 × 選択件数 × 結果件数」のマトリクスが**単体テストで検証可能**になる。

### 3.4 ドキュメント整合

- `docs/product-requirements.md:322`「**検索ボックス**(起動直後のフォーカス位置)」が U11 以降の実態（既定は左ペイン）と乖離しているため是正する。
- `docs/functional-design.md` の「行に紐づく操作 / 行に紐づかない操作」の表（前単位で追加）に、今回有効化する2件を反映する。

## 4. 受け入れ基準

### AC-1: `Delete` による一括削除が FOLDER_TREE で動作する
- [ ] チェック選択が1件以上ある状態で左ペイン（FOLDER_TREE）にフォーカスがあるとき、`Delete` で選択全件が削除される。
- [ ] 削除は従来どおり **1アンドゥ単位**（`Ctrl/Cmd+Z` 1回で全件復元）で、完了後に選択がクリアされる。
- [ ] 一括操作バーの「削除」ボタンと**同じ結果**になる（ボタンとキーの不整合が解消される）。

### AC-2: `Delete` の単一削除は従来の制約を維持する
- [ ] チェック選択が0件のとき、FOLDER_TREE の `Delete` は**何もしない**（左ペインでは削除対象の行が定まらないため）。
- [ ] `LIST` + `listFocus === 'result'` での単一削除は従来どおり動作する。
- [ ] `LIST` + `listFocus === 'search'`（検索ボックスにキャレット）では、選択の有無にかかわらず `Delete` は**文字の前方削除**のまま。

### AC-3: `Ctrl/Cmd+A` による全件選択が FOLDER_TREE で動作する
- [ ] FOLDER_TREE で `Ctrl/Cmd+A` を押すと、現在の表示結果が全件選択される。
- [ ] `LIST` + `listFocus === 'search'` では従来どおり素通しし、ネイティブのテキスト全選択が働く。
- [ ] `LIST` + `listFocus === 'result'` では従来どおり全件選択される。

### AC-4: 既存ショートカットの挙動が変わらない（回帰なし）
- [ ] `F2` / `Ctrl+E`（インライン編集）・`Ctrl+;`（別名編集）・`Ctrl+M`（選択なし＝単一移動）は **LIST 限定のまま**。
- [ ] `Ctrl+D`（現在ページ登録）・`Ctrl+M`（選択あり＝一括移動）・`Ctrl+Z`（アンドゥ）は前単位のとおり LIST / FOLDER_TREE の両方で有効。
- [ ] `INLINE_EDIT` / `ALIAS_EDIT` / `PANEL` / `DRAG` では、いずれのショートカットも**横取りしない**。
- [ ] 各ショートカットの `results.length` に関する条件（結果0件時の無効化）が従来と一致する。

### AC-5: 有効条件が純粋関数に集約され単体テストされている
- [ ] `modeMachine.ts` に `isShortcutEnabled(intent, ctx)` があり、React / DOM / `chrome.*` に非依存。
- [ ] `Popup.tsx` の7つのショートカット条件式が、すべて `isShortcutEnabled` の呼び出しに置き換わっている

- [ ] **前単位で起きた3件のバグが、このテストで再現・検出できる**（＝修正前の条件ならテストが落ちる）。

## 5. スコープ外

| 項目 | 理由 |
|---|---|
| `docs/ideas/keyboard-first-navigation.md:76` の旧仕様記述 | **意図的に据え置く**。`ideas/` は壁打ち成果物（当時の検討記録）であり、書き換えると議論の履歴が失われる。永続ドキュメントが正 |
| `resolveShortcutIntent`（キー → インテントの解決）の変更 | 今回変わるのは「有効条件」のみ。キー割り当て自体は不変 |

| React コンポーネントの結合テスト導入 | プロジェクト方針（純粋ロジックのみテスト）を維持。本単位は「純粋関数へ切り出してテスト可能にする」方向で解決する |

## 6. 解釈で埋めた点（設計判断・**異論があれば計画承認時に指摘してほしい**）

1. **ツリー操作中の `Delete` で右ペインのブックマークを消してよい** — 前単位のゲート2 で
   「破壊的操作であり、ツリー上の `Delete` には『フォルダを削除』という別解釈の余地がある」として保留した点。
   今回「未対応のバグを修正」との指示を受けたため、**有効化する判断で計画する**。根拠は
   (1) 一括操作バーに「N件選択中」と表示され文脈が可視化されている、(2) 5秒アンドゥがある、
   (3) 一括操作バーの「削除」ボタンが既に同じことをしている（キーだけ効かないほうが不整合）。
   - ⚠️ 「FOLDER_TREE では `Delete` を無効のままにする（＝ボタン経由のみ）」としたい場合は承認時に指示してほしい。
2. **`isShortcutEnabled` の切り出しまでを本単位に含める** — 指示は「バグを修正」だが、今回のバグは
   「テストで検出できない構造」そのものが原因であり、同じ修正を3度繰り返している。切り出しにより
   AC-5 の形で**修正が正しいことをテストで示せる**ようになるため、修正手段として含める。
   - ⚠️ 最小修正（`Popup.tsx` の2箇所を共通ブロックへ移すだけ・テストなし）に絞りたい場合は承認時に指示してほしい。
3. **`select-all` の「検索ボックスでは素通し」条件を維持する** — FOLDER_TREE で有効化しても、
   検索ボックスにキャレットがある間はネイティブのテキスト全選択を優先する（既存の意図を変えない）。
4. **`undo` の `undoPending` 判定は `Popup.tsx` に残す** — トースト保持の有無はモード/フォーカスと無関係な
   外部状態のため、`isShortcutEnabled` はモード・フォーカス・件数による有効性のみを判定する。
