# 要求内容 — folder-delete（フォルダの削除）

## 概要

左ペインのフォルダを**右クリックメニューから削除**できるようにする。中身のあるフォルダは件数付きの確認ダイアログを挟み、削除後は5秒の即時アンドゥ（第1層）と30日ゴミ箱（第2層）の既存2層防御で保護する。ゴミ箱へは**配下ツリーごと1項目**（`kind: 'folder'`）で退避し、復元でフォルダ構造ごと戻る。

## 背景

**現状、フォルダを削除する手段が一切ない**（調査で確認）。

- 左ペイン `FolderTree` / `FolderTreeItem` に削除の導線は無い（押下対象は「展開三角」と「フォルダ名＝スコープ選択」の2つのみ）。
- `useRowActions.deleteRow` は `if (!url) return true;` で**URL を持たない行＝フォルダを明示的に除外**しており、`deleteRows`（一括）も同様にフィルタしている。
- データ層の `BookmarkService.remove` は `chrome.bookmarks.remove` の薄いラッパで、**中身のあるフォルダには使えない**（Chrome は非空フォルダに対してエラーを投げる。`removeTree` が必要）。

一方で**受け皿は既に用意されている**:

- `TrashStore` は `kind: 'folder'` を前提に実装済み。`push` は `children` を再帰的に採番し、`restore` は `restoreInto` でフォルダを作り直して子孫を再帰復元する。
- オプションの「ゴミ箱」タブ（`TrashTab.tsx`）は `kind === 'folder'` を 📁 アイコンと配下件数（`countLeaves`）で表示する分岐を持つ。
- PRD 機能12 の受け入れ条件にも「**フォルダ削除時は配下ツリーごと丸ごと保存する**」と明記されている。

つまり「削除された結果を受け取る側」だけが先に実装され、**削除する側が欠けている**状態であり、本単位はその欠落を埋める。

## 決定事項（本要求の作成時にユーザーと確定）

| # | 論点 | 決定 |
|---|---|---|
| 1 | 削除の入口 | **フォルダ行の右クリックメニュー**（コンテキストメニュー）。行ホバーの🗑アイコンや専用ショートカットは追加しない |
| 2 | 確認ダイアログ | **中身があるときだけ**確認する。空フォルダ（ブックマーク0件かつサブフォルダ0件）は即削除 |
| 3 | ゴミ箱への入れ方 | **フォルダ丸ごと1項目**（`kind: 'folder'` + `children` 再帰）。復元もフォルダ構造ごと1回で戻る |
| 4 | 削除後のスコープ | **親フォルダへ移す**（親が無い＝最上位なら「すべて」へ） |

## 実装対象の機能

### 1. データ層の拡張（`BookmarkService`）

- `removeTree(id)`: `chrome.bookmarks.removeTree` のラッパ。**中身ごとフォルダを削除する**（既存 `remove` は非空フォルダに使えないため新設する。`remove` は単一ブックマーク用として残す）。
- `getSubTree(id)`: `chrome.bookmarks.getSubTree` のラッパ。削除前にゴミ箱退避用のツリーを取得する。

### 2. 純粋モデル（`folderDeleteModel.ts`）

削除に必要な「木の読み替え」を副作用なしの関数に集約し、ユニットテストで固定する。

- `countContents(node)`: 配下のブックマーク数・フォルダ数を数える（確認ダイアログの文言用）。
- `collectBookmarkIds(node)`: 配下のブックマーク（`url` を持つノード）の ID を集める（検索索引から落とす対象）。
- `toTrashInput(node, folderPath, aliasesOf)`: 部分木を `TrashInput`（`kind: 'folder'` + `children` 再帰）へ写像する。各ブックマークの別名は `aliasesOf(url)` で解決して埋める（復元時に別名まで戻すため）。
- `collectBookmarkUrls(node)`: 配下ブックマークの URL 一覧（別名レコードの除去対象）。
- `resolveScopeAfterDelete(folders, scopeFolderId, deletedId, parentId)`: 削除対象が現在のスコープ**またはその祖先**なら親フォルダ ID（無ければ `null`＝すべて）を、無関係ならスコープ据え置きを返す（決定事項4）。

### 3. 削除オーケストレーション（`useFolderActions.ts`）

`useRowActions` と同じ骨格（データ層 → 索引更新 → 再検索 → アンドゥ登録 → 失敗はトースト）で、フォルダ削除を1箇所に集約する。

`deleteFolder(folderId, title, folderPath)`:
1. `getSubTree` で部分木を取得し、`aliasStore.getAll()` の結果から別名を解決して `TrashInput` を組み立てる（**削除前**に退避データを作る）。
2. `bookmarkService.removeTree(folderId)` で削除する。失敗したらエラートーストのみ出して中断（索引は触らない）。
3. 配下ブックマークの別名レコードを `aliasStore.remove(url)` で除去する（失敗はログのみ・削除自体は成功扱い。`deleteRow` と同じ規律）。
4. `trashStore.push(trashInput)` でゴミ箱へ退避する（失敗はログのみ）。
5. `searchEngine.removeNode(id)` を配下ブックマーク全件に適用し、`refresh()` で再検索する。
6. 5秒の即時アンドゥを登録する。アンドゥは `trashStore.restore(trashId)` でフォルダ構造ごと復元し、**検索索引の再構築**と**左ペインの再読み込み**を行う（復元後の ID は新規採番のため、部分更新ではなく再構築で整合させる）。

### 4. 右クリックメニュー（`FolderContextMenu.tsx`）

- フォルダ行の右クリック（`onContextMenu`）で、カーソル位置にメニューを開く（ブラウザ既定のメニューは `preventDefault` で抑止）。
- 項目は「削除」1つ（本単位のスコープ）。将来のフォルダ操作（リネーム・新規作成）を足せる構造にする。
- **最上位フォルダ**（「ブックマーク バー」「その他のブックマーク」等 = ツリーの深さ0）では削除を**無効表示**にする（Chrome がルート直下のフォルダの削除を拒否するため）。
- 「すべて」行・「さらに N 件…」行では**メニューを開かない**（削除対象が存在しないため）。
- 開いている間はモード状態機械の `PANEL` として扱い、既存の全ショートカット（`Delete` / `Ctrl+M` / 検索ファースト復帰など）を抑止する。`↑↓` で項目移動・`Enter` で実行・`Escape` / 枠外クリックで閉じる。
- 画面（760×560）の外へはみ出さないよう位置を内側へ丸める。

### 5. 確認ダイアログ（`ConfirmDialog.tsx`）

- **中身のあるフォルダのみ**表示する（決定事項2）。文言に対象名と内訳件数を出す（例: 「"chrome" を削除します。中のブックマーク 12 件・フォルダ 3 件も一緒に削除されます。」）。
- ボタンは [削除する]（危険色）と [キャンセル]。**既定フォーカスは [キャンセル]**（破壊的操作を Enter 連打で誤発火させない）。
- `↑↓` / `←→` でボタン間を移動、`Enter` でフォーカス中のボタンを実行、`Escape` / 枠外クリックでキャンセル。メニューと同じく `PANEL` モードで扱う。

### 6. 左ペインの追従（`FolderTree` / `Popup`）

- 削除・アンドゥの後に**フォルダツリーを再読み込み**する（現在は起動時に1回しか取得しないため、削除しても左ペインに残ってしまう）。`actionsRef`（既存の命令ハンドル）に `reload()` を追加して実現する。
- 削除対象が現在のスコープまたはその祖先なら、スコープを親フォルダへ移す（決定事項4）。
- 削除・アンドゥの後にキーボードフォーカスは**左ペイン**へ戻す（操作の起点がそこであるため）。

## 受け入れ基準

- [ ] **AC-1（メニューの表示）**: 左ペインのフォルダ行を右クリックすると、ブラウザ既定のメニューではなく「削除」を含む独自メニューがカーソル位置に開く。「すべて」行・「さらに N 件…」行では開かない。
- [ ] **AC-2（最上位フォルダの保護）**: 「ブックマーク バー」等の最上位フォルダでは削除項目が無効表示になり、実行できない。
- [ ] **AC-3（空フォルダの即削除）**: 中身が無いフォルダは確認なしで削除され、左ペインから消える。
- [ ] **AC-4（中身ありの確認）**: 中身のあるフォルダでは確認ダイアログが出て、対象名と内訳件数（ブックマーク数・フォルダ数）が表示される。[キャンセル] / `Escape` では**何も削除されない**。
- [ ] **AC-5（配下ごと削除）**: [削除する] で、そのフォルダと配下の全ブックマーク・全サブフォルダが削除され、検索結果からも消える。
- [ ] **AC-6（即時アンドゥ）**: 削除後5秒のトーストの「元に戻す」で、フォルダ構造・配下ブックマーク・別名が元の階層へ戻り、左ペインと検索結果の両方に復帰する。
- [ ] **AC-7（ゴミ箱）**: 削除したフォルダがゴミ箱に `kind: 'folder'` の**1項目**として入り、オプションの「ゴミ箱」タブに 📁 と配下件数付きで表示され、そこからの復元でもフォルダ構造ごと戻る。
- [ ] **AC-8（スコープの追従）**: 削除したフォルダが現在のスコープまたはその祖先だった場合、スコープが親フォルダ（無ければ「すべて」）へ移る。無関係なフォルダの削除ではスコープは動かない。
- [ ] **AC-9（キーボード）**: メニュー・確認ダイアログとも `↑↓` で移動・`Enter` で実行・`Escape` で閉じられる。確認ダイアログの既定フォーカスは [キャンセル]。開いている間は既存のショートカット（`Delete` 等）が発火しない。
- [ ] **AC-10（失敗時の整合）**: 削除が失敗した場合はエラートーストを出し、検索索引・左ペインの表示を実データと食い違わせない。
- [ ] **AC-11（品質ゲート）**: `pnpm test` / `pnpm lint` / `pnpm type-check` が通る。`folderDeleteModel`（件数集計・`TrashInput` 変換・スコープ解決）と `BookmarkService.removeTree`/`getSubTree` にユニットテストがある。

## 成功指標

- フォルダの整理がポップアップ内で完結する（現在はフォルダを消すためだけに Chrome のブックマークマネージャーへ離脱する必要がある）。
- 誤ってフォルダを消しても、5秒アンドゥとゴミ箱の2層で必ず取り戻せる（データ損失ゼロ）。

## スコープ外

- フォルダの**リネーム・新規作成・移動**（メニューは項目を足せる構造にするが、本単位では「削除」のみ）。
- 複数フォルダの一括削除・フォルダと結果行の混在選択（U13 の複数選択は結果行のみが対象のまま）。
- ゴミ箱タブ側の UI 変更（`kind: 'folder'` の表示・復元は実装済みのものをそのまま使う）。
- 右クリックメニューの**結果行（右ペイン）への展開**（右ペインの操作系は既存のホバーアイコン・ショートカットのまま）。
- 削除したフォルダの展開状態（`localStateStore.expandedFolderIds`）の即時掃除（存在しないフォルダ ID は U17 の Service Worker 起動時クリーンアップが除去する）。
