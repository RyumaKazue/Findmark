# 要求内容 — selection-mode（選択モードへの切り替え方式）

## 概要

複数選択の入口を「行ホバーで現れる**左のチェックボックス**」から「ヘッダーの**選択モード切替ボタン**」へ変更する。左のチェックボックスは通常モードから**廃止**し、選択モード中は**行のどこを押しても選択トグル**（＝開かない）になる。移動 / 削除の一括操作そのもの（1アンドゥ単位）は現行のまま維持する。

## 背景

U13（`.steering/20260808-multi-select-bulk/`）で Gmail / Finder 型の選択 UI を実装した。現行は次の仕様になっている。

- 行ホバーでファビコン位置が 16px のチェックボックスに変化し、それを押すと選択される（`ResultRow.tsx` の `data-checkbox-area`）。
- チェックボックス以外の場所を押すと**ブックマークが開く**（現在タブ遷移＝ポップアップが閉じる）。

**問題**: 選択の唯一のマウス導線が 16×16px のチェックボックスに集中しており、その周囲（タイトル・ファビコン周辺の余白）を押すと**意図せずサイトが開いてポップアップが閉じる**。整理作業中の誤操作としてコストが大きく（作業文脈が失われる）、ターゲットも小さい。「同じ行の中で、数 px の差で『開く』と『選ぶ』が切り替わる」という設計そのものが誤操作の温床になっている。

**解決**: 「開く」と「選ぶ」を**モードで分離**する。通常モードでは行はすべて「開く」、選択モードでは行はすべて「選ぶ」。行内に境界を作らないため、どこを押しても意図した結果になる。

## 決定事項（本要求の作成時にユーザーと確定）

| # | 論点 | 決定 |
|---|---|---|
| 1 | 選択モードの入口 | **ヘッダーの「＋追加」の左**に「☑ 選択」トグルボタンを置く（常時表示・56px ヘッダー内） |
| 2 | 選択済みの見せ方 | **選択モード中のみ**ファビコン位置を 16px チェックボックスに置換（design 1f の見た目のまま）。ただし**表示専用**で、押下判定は行全体。通常モードではホバーしてもチェックボックスは出さない |
| 3 | 一括操作の完了後 | 選択をクリアし、**選択モードも自動解除**して通常モード（クリック＝開く）へ戻す |
| 4 | 修飾キー操作 | 通常モードでも `Ctrl/Cmd+クリック` / `Shift+クリック` / `Ctrl/Cmd+A` は有効。実行すると**選択が発生すると同時に選択モードへ自動遷移**する（＝選択件数>0 と選択モード ON が常に整合する） |

## 実装対象の機能

### 1. 選択モードという状態（`selectionModel.ts` / `useSelection.ts`）

- 選択状態（`{ ids, anchorId }`）に **`active: boolean`（選択モードか）** を加える。
- 純粋操作を追加/改訂する:
  - `activate` / `deactivate`: モードの開始・終了。`deactivate` は **ids と anchor もクリア**する（「終了＝選択も捨てる」を1箇所で保証する）。
  - `toggle` / `rangeTo` / `selectAll`: 選択が発生したら `active` を **true** にする（決定事項4の「自動遷移」を純粋モデル側の不変条件として持つ）。
  - `clear`: **ids と anchor のみ**をクリアし `active` は保つ（クエリ / スコープ変更時に使う。検索し直して選び直す動線を壊さないため）。
- 不変条件: **`ids.size > 0` ならば `active === true`**（選択があるのにモードが OFF、という状態を作らない）。

### 2. ヘッダーの選択モード切替ボタン（`SearchHeader.tsx`）

- 検索ボックスの右、「＋追加」の**左**に「☑ 選択」トグルボタン（h34）を置く。
- ON / OFF がひと目で分かる見た目にする（OFF = 白地 + 枠 / ON = accent 塗り）。`aria-pressed` を付ける。
- 文言は i18n（`commonSelect`）を使い、ツールチップは ON / OFF で出し分ける（新規キーを `ja` / `en` へ追加）。

### 3. 行の操作体系の変更（`ResultRow.tsx` / `ResultList.tsx`）

- **通常モード**: 行のどこを押しても「開く」。**チェックボックスはホバーしても一切表示しない**（`data-checkbox-area` とホバー段階表示を撤去）。別名エリアクリック（別名編集）・ホバーの ✎ / 🗑 アイコン・ダブルクリック（インライン編集）は従来どおり。
- **選択モード**: 行のどこを押しても**選択トグル**（開かない）。`Shift+クリック` は範囲選択。行内の編集導線（✎ / 🗑 アイコン・別名エリア・ダブルクリック）は**無効化し、アイコンは表示しない**（押せるものが減り、押下対象が「行」1つに単純化される）。
- ファビコン位置は選択モード中のみ 16px チェックボックス（design 1f の見た目）に置換する。**表示専用**（`pointer-events-none`）で、クリック判定は行全体が受ける。切替でレイアウトが動かない（同寸）。

### 4. キーボードの整合（`modeMachine.ts` / `Popup.tsx`）

- `Enter`（`list:open`）は「フォーカス中の行を活性化する」の意味を保ち、**選択モード中は選択トグル**として働く（マウスのクリックと同じ意味論にする）。
- `isShortcutEnabled` の判定文脈に `selectionMode` を加える:
  - `inline-edit` / `alias-edit`: 選択モード中は**無効**（行の編集導線を止める方針と一致させる）。
  - `delete` / `panel`（`Ctrl/Cmd+M`）: 選択モード中は**選択件数 > 0 のときのみ**有効（選択モードに入った直後の誤爆で、選ぶつもりだったフォーカス行が消える事故を防ぐ）。通常モードでの単一行への適用は従来どおり。
  - `select-all`（`Ctrl/Cmd+A`）: 従来どおり（実行すると選択が発生し、モデル側の不変条件により選択モードへ入る）。
- `Escape`: 選択モード中は**モード終了（＋選択クリア）**を最優先の1段目にする（現行は「選択クリア」だけだった）。以降の段階戻り（検索ボックスへ戻る → キーワードクリア → スコープ解除 → 閉じる）は不変。

### 5. 一括操作との接続（`Popup.tsx` / `BulkActionBar.tsx`）

- 1件以上選択中はヘッダーが `BulkActionBar` へ差し替わる（現行どおり）。選択0件の選択モード中は `SearchHeader`（ボタン ON 表示）のまま＝**選択モード中も検索できる**。
- 一括移動 / 一括削除の完了、および `BulkActionBar` の「選択解除」で、選択モードを終了する（決定事項3）。
- ドラッグ&ドロップは現行のまま（選択中の行をドラッグすれば全件を運ぶ・件数バッジ）。

## 受け入れ基準

- [ ] **AC-1（通常モードの単純化）**: 通常モードでは行のどこを押しても対象が開く。行にホバーしてもチェックボックスは表示されない。
- [ ] **AC-2（モード入口）**: ヘッダーの「☑ 選択」ボタンで選択モードに入り、もう一度押すと出る。ON / OFF がボタンの見た目で判別できる。
- [ ] **AC-3（行クリック＝選択）**: 選択モード中は行のどこを押しても選択がトグルし、**ブックマークは開かない**。`Shift+クリック` で範囲選択できる。フォーカス行への `Enter` も選択トグルになる。
- [ ] **AC-4（選択の視認）**: 選択モード中は全行のファビコン位置がチェックボックスになり、選択済みは accent 塗り + 白 `✓` + 行背景 `#F4F6FE`、未選択は白枠。切替でレイアウトが動かない。
- [ ] **AC-5（一括操作の維持）**: 1件以上選択でヘッダーが「N件選択中 [移動] [削除] [選択解除]」に切り替わり、一括移動 / 一括削除が**1回のアンドゥで全戻し**になる（U13 の挙動を退行させない）。
- [ ] **AC-6（操作後の自動復帰）**: 一括移動 / 一括削除の完了後、選択がクリアされ選択モードも解除され、行クリックが「開く」に戻る。
- [ ] **AC-7（修飾キーからの自動遷移）**: 通常モードでの `Ctrl/Cmd+クリック` / `Shift+クリック` / `Ctrl/Cmd+A` は選択を発生させ、同時に選択モードへ入る（選択件数 > 0 と選択モード ON が常に一致する）。
- [ ] **AC-8（終了導線）**: 「☑ 選択」ボタン再押下 / `Escape` / 一括操作バーの「選択解除」のいずれでも、選択モードが終了し選択もクリアされる。
- [ ] **AC-9（選択モード中の無効化）**: 選択モード中は ✎ / 🗑 アイコンが表示されず、ダブルクリック・別名エリアクリック・`F2` / `Ctrl+E` / `Ctrl+;` で編集に入らない。`Delete` / `Ctrl+M` は選択0件のとき何も起きない。
- [ ] **AC-10（検索との両立）**: 選択モード中にクエリ / スコープを変えると選択はクリアされるが、**選択モードは維持**される（選び直せる）。
- [ ] **AC-11（品質ゲート）**: `pnpm test` / `pnpm lint` / `pnpm type-check` が通る。`selectionModel` の `active` 遷移と `isShortcutEnabled` の選択モード分岐にユニットテストがある。

## 成功指標

- 「整理しようとして誤ってサイトが開く」経路が構造的に消える（通常モードでは選択操作が無く、選択モードでは開く操作が無い）。
- マウスの押下対象が「16×16px のチェックボックス」から「56px の行全体」へ広がる（Fitts の法則の観点で誤操作率が下がる）。

## スコープ外

- 一括操作の中身（`moveRows` / `deleteRows` / アンドゥ単位 / ゴミ箱連携）の変更。U13 / U16 の実装をそのまま使う。
- 選択のクエリ横断保持（クエリ / スコープ変更で選択はクリアのまま）。
- 選択モードの状態をポップアップの再起動に跨いで永続化すること（U19 の `PopupSession` には保存しない。開くたび通常モードから始める）。
- 一括操作バーへの新規ショートカット追加（`Ctrl+M` / `Delete` の流用のみ）。
- 左ペイン（フォルダツリー）の複数選択。
