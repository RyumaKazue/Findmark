# 要求内容 — folder-rename-create（フォルダの名前変更・新規作成）

## 概要

左ペインのフォルダ右クリックメニューに、**「新しいフォルダ」**と**「名前を変更」**の2項目を追加する。現在このメニューは「フォルダを削除」の1項目しか持たず、フォルダの整理をポップアップ内で完結できない（名前を直すにも、受け皿のフォルダを1つ作るにも、Chrome のブックマークマネージャーへ出る必要がある）。

## 背景

- `folder-delete`（2026-08-16）で左ペインに右クリックメニューを導入し、`row-context-menu`（同日）で結果行にも広げた。`ContextMenu` は**項目配列駆動**で作られており、`folder-delete` の design.md にも「フォルダのリネーム・新規作成……を項目追加だけで足せる」と申し送りが残っている。本単位はその申し送りを回収する。
- Findmark は「ブックマークを探す」だけでなく「その場で整理する」ことを掲げており、結果行に対しては編集・別名・移動・削除が揃っている（機能4）。一方フォルダ側は**削除だけ**が可能という非対称な状態にある。フォルダを作れないため、「移動先のフォルダを新しく作ってそこへ整理する」という一連の流れが途中で外部アプリへ落ちる。
- データ層は既に揃っている。`BookmarkService.rename(id, title)` と `BookmarkService.create({ title, parentId })` は U10 / U14 で実装済みで、本単位でのデータ層の拡張は**不要**。

- 引用元:
  - `docs/product-requirements.md` 機能5「フォルダスコープ」— 本単位で受け入れ条件を追記する
  - `docs/functional-design.md` UC-5b「フォルダの削除(右クリックメニュー)」— 隣に UC-5c を追記する
  - `.steering/20260816-folder-delete/design.md`「将来の拡張性」— 本単位が回収する申し送り
  - `pages/popup/src/components/ContextMenu.tsx` / `rowMenuModel.ts`（項目配列駆動のメニュー）

## 決定事項（本要求の作成時に確定）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | メニューの項目構成 | 「新しいフォルダ」→「名前を変更」→（区切り線）→「フォルダを削除」の3項目 | `rowMenuModel` と同じ「非破壊 → 破壊」の並び。破壊的な削除を区切り線で離す規律を踏襲する |
| 2 | 名前の入力 UI | **汎用の `PromptDialog`**（`ConfirmDialog` と同じ PANEL モードのモーダル・単一テキスト入力）。ツリー行内のインライン編集は**非採用** | 左ペインは 220px 幅 + 横スクロール + インデントで、行内に入力欄を出すと文字がほとんど見えない。加えて `FolderTree` は「スコープ＝フォーカス行」という単一状態でキー操作を組んでおり、行内編集を足すとそのモデルを壊す。1つの `PromptDialog` で名前変更と新規作成の両方をまかなえる |
| 3 | 新規フォルダの作成先 | 右クリックしたフォルダの**直下**（サブフォルダとして作る） | 「すべて」行にメニューを付けなくても、最上位フォルダ（「ブックマーク バー」等）を右クリックすればその直下に作れる。作成先を選ばせる UI を増やさずに全階層をカバーできる |
| 4 | 最上位フォルダの扱い | 「名前を変更」は**無効項目**（理由をツールチップ表示）。「新しいフォルダ」は**有効** | Chrome がルート直下のフォルダ（ブックマーク バー / その他のブックマーク）の `update` を拒否する。削除と同じく「押せない理由が分かる」状態にする。作成は拒否されないため制限しない |
| 5 | 名前のバリデーション | 空文字・空白のみは確定不可（確定ボタンを無効化）。前後の空白は trim して保存。**同名は許可** | Chrome 自身が同名フォルダを許可しており、ここだけ禁止すると操作が通らない理由が分からない。`folder-scope-descendants` 以降スコープ判定は ID で行うため、同名でも取り違えは起きない |
| 6 | アンドゥ（5秒トースト） | **登録しない** | 既存の規律に合わせる。5秒アンドゥは**破壊的操作**（削除・移動）にのみ登録しており、リネーム（`useRowActions.editRow`）には登録していない。名前変更も新規作成も、同じメニューから即座に取り消せる（もう一度名前を変える / 作った空フォルダを削除する）ため、第2の取り消し経路を増やす価値が薄い |
| 7 | 名前変更後の検索索引 | **索引を作り直す**（`reloadIndex`） | 索引エントリは配下ブックマークごとに `folderPath` / `nFolders`（フォルダ名の照合語）を持つ。フォルダ名の変更は配下**全エントリ**に波及するため、部分更新（`moveNode` 等）では追随できない |
| 8 | 新規作成後の見せ方 | 親フォルダを展開し、**作成したフォルダをスコープにする** | 作成の結果が左右のペインに即座に現れる。作った直後は「そこに入れる」ことが目的なので、スコープを合わせておくと次の操作（D&D・移動）にそのまま繋がる |

## 実装対象の機能

### 1. メニュー項目の追加（`folderMenuModel` 新設 + `ContextMenu` への配線）

- フォルダメニューの項目は現在 `Popup.tsx` の JSX に直書きされている（`folder-delete` 時点では1項目だったため）。3項目 + 無効条件 + 区切り線になるため、**`rowMenuModel.ts` と同じ純粋モジュール `folderMenuModel.ts` へ切り出す**。
- 無効条件（最上位フォルダでは名前変更・削除が不可）を純粋関数に閉じ、ユニットテストで固定する。

### 2. 名前入力ダイアログ（`PromptDialog` 新規・汎用）

- 見出し・入力ラベル・初期値・確定ボタンのラベルを呼び出し側から受ける汎用コンポーネント。フォルダ固有の文言は持たない。
- `Enter` で確定・`Escape` でキャンセル。開いた直後に入力欄へフォーカスし、名前変更のときは**全選択**する（書き換えが主用途）。
- 空文字・空白のみのときは確定ボタンを無効化する。

### 3. フォルダ操作の追加（`useFolderActions`）

- `renameFolder({ id, title })`: `bookmarkService.rename` → 索引の再構築 → 左ペイン再取得。
- `createFolder({ parentId, title })`: `bookmarkService.create` → 左ペイン再取得。作成したフォルダの ID を返す（スコープ追従に使う）。

### 4. 結線（`Popup.tsx`）

- `ContextAction` ユニオンに `folder-prompt` variant を1つ追加する（既存の排他条件 `contextAction === null` は増やさない）。
- PANEL のキー配線を、`folder-confirm` → 確認ダイアログ / `folder-prompt` → 入力ダイアログ / それ以外 → メニュー、の3分岐にする。

### 5. 影響範囲の確認（変更しないもの）

- **データ層は拡張しない**（`rename` / `create` は実装済み）。
- 「すべて」行・「さらに N 件…」行のメニューは追加しない（決定事項3）。
- 結果行の右クリックメニュー（`row-context-menu`）は変更しない。
- フォルダの移動・削除・D&D・複数選択・ゴミ箱は影響を受けない。

## 受け入れ基準

- [ ] **AC-1（メニュー項目）**: フォルダ行を右クリックすると「新しいフォルダ」「名前を変更」「フォルダを削除」の3項目が、この並びで表示される。「フォルダを削除」の上に区切り線がある。
- [ ] **AC-2（名前変更）**: 「名前を変更」を選ぶと現在の名前が入った入力欄が開き、変更して確定すると左ペインの表示名が変わる。
- [ ] **AC-3（名前変更と検索の整合）**: 名前変更後、配下ブックマークの行に出るフォルダパス表示と、**フォルダ名での検索ヒット**が新しい名前に追随する。
- [ ] **AC-4（新規作成）**: 「新しいフォルダ」を選んで名前を入力し確定すると、**右クリックしたフォルダの直下**に空フォルダが作られ、左ペインに現れる。
- [ ] **AC-5（作成後のスコープ）**: 作成直後、親フォルダが展開され、作成したフォルダがスコープ（左ペインのフォーカス行）になる。
- [ ] **AC-6（最上位の制限）**: 最上位フォルダ（「ブックマーク バー」等）では「名前を変更」「フォルダを削除」が無効表示になり、理由がツールチップで分かる。「新しいフォルダ」は有効で、実際に直下へ作成できる。
- [ ] **AC-7（空名の拒否）**: 名前が空・空白のみのときは確定できない（ボタンが無効）。前後の空白は取り除いて保存される。
- [ ] **AC-8（変更なしの確定）**: 名前を変えずに確定した場合、chrome API を呼ばずにダイアログを閉じるだけで、索引の再構築も起きない。
- [ ] **AC-9（キーボード完結）**: 入力欄で `Enter` 確定・`Escape` 取りやめができる。取りやめると何も変更されず、フォーカスは左ペインへ戻る。日本語入力の変換確定 `Enter` でダイアログが閉じない。
- [ ] **AC-10（失敗時の扱い）**: 名前変更・作成が失敗した場合はエラートーストを出し、左ペイン・索引は変更しない（表示と実データの乖離を作らない）。
- [ ] **AC-11（既存機能の非退行）**: フォルダ削除・結果行メニュー・移動（D&D / Ctrl+M）・複数選択・検索・状態復元がすべて従来どおり動く。
- [ ] **AC-12（品質ゲート）**: `pnpm test` / `pnpm lint` / `pnpm type-check` が通る。メニュー項目の組み立てと名前のバリデーションにユニットテストがある。

## 成功指標

- フォルダの整理（作る・名前を直す・消す）がポップアップ内で完結し、Chrome のブックマークマネージャーへ出る必要がなくなる。
- 「移動先のフォルダを作ってからそこへ移す」という流れが、ポップアップを開いたまま一続きで行える。

## スコープ外

- **フォルダの移動**（フォルダ自体を別の親へ移す）。ブックマーク行の移動とは D&D の対象・`MovePanel` の候補計算（自分自身とその子孫を除外する必要がある）が変わるため、別単位とする。
- 「すべて」行からの新規作成（決定事項3）。
- ショートカットキーの割り当て（`F2` でフォルダ名変更など）。右クリックメニューを唯一の導線とし、ショートカットの整合（`modeMachine.isShortcutEnabled`）は別単位で検討する。
- フォルダ名変更・作成の5秒アンドゥ（決定事項6）。
- フォルダの並び替え・アイコン変更・色分け。
