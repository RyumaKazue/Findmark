# 要求内容 — row-context-menu（ブックマーク行の右クリックメニュー）

## 概要

検索結果の行（ブックマーク）にも**フォルダと同じ右クリックメニュー**を出し、編集・別名を編集・フォルダへ移動・削除をそこから実行できるようにする。あわせて、行ホバーで右端に現れる **✎／🗑 アイコンを廃止**し、行内の操作導線をメニューに一本化する。

## 背景

`folder-delete`（2026-08-16）で左ペインのフォルダに右クリックメニューを導入した。一方、右ペインのブックマーク行の操作は次のように**行内に小さな押下対象が点在**したままになっている。

- **✎／🗑 アイコン**: ホバー時に行の右端へフェードインする 24px 角の領域（`ResultRow.tsx` の `data-row-action`）。
- **別名チップ領域**: 2段目のチップ付近をクリックすると別名編集に入る（`data-alias-area`）。
- それ以外の場所をクリックすると**ブックマークが開く**（現在タブ遷移＝ポップアップが閉じる）。

これは `selection-mode`（2026-08-15）で解消したのと**同じ構造の問題**である。あの単位では「行の中に数 px の境界があり、押す場所によって『開く』と『選ぶ』が切り替わる」ことが誤操作の原因だと結論づけ、境界そのものを無くした。しかし ✎／🗑 と別名エリアという境界は残っており、「削除しようとして 🗑 の隣を押し、サイトが開いてポップアップが閉じる」経路が残っている。

同時に、**発見しにくさ**の問題もある。別名編集は Findmark の中核機能（PRD 機能2）だが、マウスでの入口は「2段目のチップ付近をクリックする」という手掛かりの薄い操作しかない。フォルダ移動に至っては `Ctrl+M` かドラッグ&ドロップを知らなければ到達できない。右クリックメニューは、行に対してできることを**一覧として提示する**ため、この2つを同時に解決する。

## 決定事項（本要求の作成時にユーザーと確定）

| # | 論点 | 決定 |
|---|---|---|
| 1 | ホバーの ✎／🗑 アイコン | **廃止**し、右クリックメニューに一本化する |
| 2 | メニューの項目 | **編集 / 別名を編集 / フォルダへ移動… /（区切り）/ 削除** の4つ |
| 3 | 選択モード中の右クリック | **メニューを出さない**（一括操作バーが担う既存の役割分担を崩さない） |
| 4 | メニューの見た目・操作 | フォルダ側と**同じコンポーネント**を使う（本単位で汎用化する） |
| 5 | 別名チップ領域のクリック | **維持する**（廃止案を提示したがユーザー判断で存置）。押下範囲が狭く誤爆しにくいこと、別名を頻繁に付け替える操作ではないことが理由 |

## 実装対象の機能

### 1. メニューコンポーネントの汎用化（`FolderContextMenu` → `ContextMenu`）

- `folder-delete` で作った `FolderContextMenu` はフォルダ固有の要素を持たない（項目配列・座標・命令ハンドルのみ）。**名前だけがフォルダ専用**なので、`ContextMenu` / `ContextMenuActions` / `MenuItem` へ改名して行からも使う。
- 項目に**区切り線**（`separatorBefore`）を追加する。破壊的な「削除」を他の項目から視覚的に離すため（決定事項2 の並び）。

### 2. ブックマーク行の右クリック（`ResultRow` / `ResultList` / `Popup`）

- 行のどこを右クリックしてもメニューが開く（ブラウザ既定のメニューは `folder-delete` で導入済みの抑止が効く）。
- **右クリックは行の状態を変えない**（フォーカス行＝`selectedIndex` を動かさない・開かない）。フォルダ側で「右クリックだけではスコープを変えない」と決めたのと同じ規律。対象行は**メニューの項目を実行した時点**で確定する。
- **選択モード中は開かない**（決定事項3）。

### 3. メニュー項目の実行（既存操作への結線）

| 項目 | 実行内容 | 既存の対応操作 |
|---|---|---|
| 編集 | インライン編集（タイトル/URL）に入る | `F2` / `Ctrl+E` / ダブルクリック |
| 別名を編集 | 別名チップ編集に入る | `Ctrl+;` |
| フォルダへ移動… | フォルダ選択パネル（`MovePanel`）を開く | `Ctrl+M` / D&D |
| 削除 | 行を削除（5秒アンドゥ + 30日ゴミ箱） | `Delete` |

- いずれも**既存のハンドラをそのまま呼ぶ**（新しい削除・編集ロジックは作らない）。対象は右クリックした行であり、実行時に `selectedIndex` をその行へ合わせる。

### 4. 行内の押下対象の整理

- **✎／🗑 アイコンを描画しない**（決定事項1）。行の右端でホバー時にだけ現れる小さな押下対象であり、隣を押すとサイトが開く誤操作の主因になっていた。
- **別名チップ領域のクリックによる別名編集は維持する**（決定事項5）。✎／🗑 と違い、押下対象が「チップそのもの」という**見えている要素に一致**しており、ホバーで現れる/消えるものでもないため、位置の取り違えが起きにくい。別名が無い行の「＋別名」破線チップも従来どおり残す（別名を付ける入口を消さない）。
  - この結果、行内の押下対象は「別名チップ領域」と「それ以外（＝開く）」の2つになる。メニューからも `Ctrl+;` からも別名編集に到達できるため、**チップのクリックは3つ目の冗長な導線**だが、既に慣れている操作を奪わないことを優先する。
- **ダブルクリックでのインライン編集は維持**する。同じ場所に対する別のジェスチャであり、「押す場所によって結果が変わる」問題を生まないため。
- キーボードショートカット（`F2` / `Ctrl+E` / `Ctrl+;` / `Ctrl+M` / `Delete`）は**すべて現状のまま**。

## 受け入れ基準

- [ ] **AC-1（メニューの表示）**: 検索結果の行を右クリックすると、フォルダと同じ見た目のメニューが「編集 / 別名を編集 / フォルダへ移動… /（区切り）/ 削除」の順で開く。
- [ ] **AC-2（右クリックは状態を変えない）**: 右クリックしてもブックマークは開かず、フォーカス行（↑↓ の基準）も動かない。`Escape` や枠外クリックで閉じれば何も起きていない状態に戻る。
- [ ] **AC-3（編集）**: メニューの「編集」でその行のインライン編集（タイトル/URL）に入る。
- [ ] **AC-4（別名を編集）**: メニューの「別名を編集」でその行の別名チップ編集に入る。
- [ ] **AC-5（フォルダへ移動）**: メニューの「フォルダへ移動…」でフォルダ選択パネルが開き、確定するとその行が移動する（5秒アンドゥ付き）。
- [ ] **AC-6（削除）**: メニューの「削除」でその行が削除され、5秒アンドゥのトーストが出る（ゴミ箱にも退避される）。
- [ ] **AC-7（アイコンの廃止）**: 行にホバーしても ✎／🗑 アイコンが表示されず、**その領域を押すとブックマークが開く**（通常モード）。
- [ ] **AC-7b（別名チップの存置）**: 別名チップ領域のクリックで従来どおり別名編集に入る。別名が無い行の「＋別名」チップも表示され、クリックで別名編集に入る。
- [ ] **AC-8（選択モード）**: 選択モード中は行を右クリックしてもメニューが開かず、ブラウザ既定のメニューも出ない。
- [ ] **AC-9（キーボード）**: メニューは `↑↓` で移動・`Enter` で実行・`Escape` で閉じる。開いた直後はどの項目もハイライトされない（`folder-delete` の挙動を踏襲）。
- [ ] **AC-10（既存操作の非退行）**: ダブルクリックでのインライン編集、`F2` / `Ctrl+E` / `Ctrl+;` / `Ctrl+M` / `Delete`、D&D での移動、複数選択と一括操作がすべて従来どおり動く。
- [ ] **AC-11（品質ゲート）**: `pnpm test` / `pnpm lint` / `pnpm type-check` が通る。メニュー項目の組み立て（対象行の有無・選択モードでの抑止）に純粋関数とユニットテストがある。

## 成功指標

- 行内の押下対象が「別名チップ領域」と「行そのもの」の2つに減り、ホバーで現れる小さな標的（✎／🗑）が消えることで、`selection-mode` で解消したのと同種の誤操作が結果行から大きく減る。
- 別名編集・フォルダ移動が、ショートカットを知らなくてもマウスだけで発見・到達できるようになる。

## スコープ外

- ブックマークを**新しいタブで開く**等、現在存在しない操作のメニュー追加（既存操作の集約に留める）。
- 複数選択に対する一括メニュー（決定事項3 のとおりメニューを出さない）。
- フォルダ側メニューへの項目追加（リネーム・新規作成）。
- 右ペインのメタ行・空状態・左ペインの「すべて」行での右クリックメニュー。
- キーボードからのメニュー起動（`Shift+F10` 等）。行に対する操作はすべて既存ショートカットで到達できるため、本単位では追加しない。
