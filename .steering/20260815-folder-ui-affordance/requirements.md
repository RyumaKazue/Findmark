# 要件定義: folder-ui-affordance（フォルダ選択 UI の操作可能性の是正）

- **作業単位名**: `folder-ui-affordance`
- **作成日**: 2026-08-15
- **指示元**: ユーザー指示「追加ダイアログのフォルダ選択で、キーボード操作でスクロールできるようにして。左ペインのフォルダにフォーカスが当たっている時、フォルダを開くボタンが見えなくなる。ユーザー目線でフォーカスが当たっていても、ここを押せばフォルダを開けると直感的にわかるようにして。」
- **依存**: `feature/shortcut-mode-parity`（コミット `0c7d1b7`）— **本単位はこの上に積む**（下記「1.1 親ブランチの注意」参照）

---

## 1. 概要

フォルダ選択まわりの**操作可能性（アフォーダンス）の欠落**を2件修正する。

1. **追加ダイアログ（`AddCurrentPanel`）の保存先フォルダ候補が、`↑↓` でスクロール追従しない** —
   選択が可視範囲の外へ出ても表示が動かず、いま何を選んでいるか分からなくなる。
2. **左ペインでスコープ中のフォルダの展開ボタン（chevron）が見えない** —
   さらに、見えるようになっても「押せば開ける」と直感的に分かる見た目になっていない。

### 1.1 親ブランチの注意（⚠️ 計画承認時に確認したい点）

`create-branch` は既定で `dev` を親にするが、**`dev` には前2単位のコミット（`c0ee558` / `0c7d1b7`）がまだ入っていない**。
本単位のコード変更自体は前単位と別ファイル（`AddCurrentPanel.tsx` / `FolderTreeItem.tsx`）のため技術的には `dev` から切っても衝突しないが、
**受け入れ検証は実機のビルド成果物で行うため、前単位の修正が入っていないビルドで確認することになり検証が混乱する**。
したがって**親ブランチは `feature/shortcut-mode-parity` とする**（前2単位に続けて積む）。
（代替案: 先に `feature/list-arrow-wrap` → `feature/shortcut-mode-parity` を `dev` へマージしてから `dev` を親にする。ユーザー判断を仰ぐ。）

## 2. 背景（何が起きているか）

### 2.1 追加ダイアログのフォルダ候補がスクロールしない

`AddCurrentPanel.tsx` の保存先フォルダのドロップダウンは、候補リストを
`<div className="max-h-[160px] overflow-y-auto p-1">`（L258）で高さ 160px に制限している。
一方 `handleFolderKeyDown`（L123-151）は `clampIndex` で `folderIndex` を動かすだけで、
**選択候補を可視範囲へ追従させる処理が無い**。

同じ用途の `MovePanel.tsx` には追従処理がある。

```ts
// MovePanel.tsx L75-78
useEffect(() => {
  listRef.current?.querySelector('[data-selected="true"]')?.scrollIntoView({ block: 'nearest' });
}, [index, filtered]);
```

`AddCurrentPanel` は `movePanelModel`（`buildMoveCandidates` / `filterCandidates` / `clampIndex`）を再利用しながら、
**この追従処理だけが移植されていない**。フォルダが 160px（＝およそ4〜5件）を超えると、`↓` を押しても
リストが動かないため選択中の候補が画面外へ消える。

### 2.2 スコープ中フォルダの chevron が見えない

`FolderTreeItem.tsx` のフォルダ行は、U11（AC-8）で**押下対象を2つに分離**した。

```
<div class="flex h-[30px] items-center">   ← 行のラッパ（背景なし）
  <IndentGuides/>
  <button chevron class="size-5 ...">      ← 展開トグル（背景なし）
  <button name    class="flex-1 ... bg-accent"> ← スコープ選択（accent 塗り）
</div>
```

スコープ中かつ左ペインがアクティブなとき、chevron は `text-white/75`（L130）になる。
しかし **accent の塗りは「フォルダ名」ボタンにしか掛かっておらず、chevron は左ペインの明るい背景の上にいる**。
結果、白 75% の記号が明るい背景に乗り、**ほぼ見えなくなる**。

これは**デザインモックからの実装上の逸脱**である。`docs/design/Findmark Popup.dc.html` L61 の選択中フォルダ行は、
**accent の塗りが chevron を含む行全体に掛かっている**。

```html
<div style="... height: 30px; padding: 0 8px; border-radius: 6px; background: var(--accent, #4F6BED); color: #FFFFFF;">
  <span style="width: 10px; ... color: rgba(255,255,255,0.75);">▾</span>
  <span style="font-size: 13px;">📁</span>extensions
</div>
```

`docs/design/README.md:101` の「選択中フォルダは accent 塗り + 白 700、三角は `rgba(255,255,255,0.75)`」も、
**塗りの内側に三角がある**ことを前提にした記述である。U11 で1つの `div` を2つの `button` に割ったとき、
塗りの範囲が「名前ボタンだけ」に縮んだのが原因。

### 2.3 「押せると分かる」見た目になっていない

U11 の AC-8 は「三角は `▸`/`▾` の素の記号ではなく、押下可能と分かる見た目（**ホバー背景を持つボタン** + chevron アイコン）にする」
と定めた。しかし現状の chevron は**ホバー時にしか背景が出ない**ため、静止状態では単なる記号にしか見えない。
キーボード操作中（＝マウスを動かさない）はホバーが起きないため、「ここを押せば開ける」という手掛かりが一切出ない。

## 3. 実装対象

### 3.1 追加ダイアログのフォルダ候補にスクロール追従を入れる

- `MovePanel` と同じ方式（`listRef` + `data-selected` + `scrollIntoView({ block: 'nearest' })`）を移植する。
- 実装が2箇所に重複するため、**追従処理は共通のカスタムフックへ切り出して両者から使う**（下記 design.md 参照）。

### 3.2 スコープ中フォルダ行の塗りを chevron まで広げる

- 行の強調（accent 塗り / 角丸）を **chevron + フォルダ名を包む内側のラッパ**に移し、デザインモックと同じ「1つの塗られた行」にする。
- インデントガイド線は塗りの**外側**に残す（design 2a のガイド線表現を壊さない）。
- 押下対象が2つに分かれている構造（U11 AC-8）は維持する。

### 3.3 chevron に常時の操作可能性を与える

- スコープ中の行では、chevron に**静止状態でも見える背景**（塗りの中で一段明るい／暗いピル）を与え、
  ホバー時にさらに強調する。
- chevron の色を上げ、塗りの上で確実に読める濃度にする。
- マウス利用者向けに `title` を付ける（現状は `aria-label` のみでツールチップが出ない）。

### 3.4 デザイン逸脱の記録

- 3.3 は `docs/design/README.md:101`（三角は `rgba(255,255,255,0.75)`・背景なし）からの意図的な逸脱になるため、
  `docs/functional-design.md`「デザイン非採用項目」へ #12 として追記する。

## 6. 解釈で埋めた点（設計判断・**異論があれば計画承認時に指摘してほしい**）

1. **「フォルダを開くボタン」= 展開/折りたたみの chevron と解釈した** — 左ペインのフォルダ行にある押下対象は
   chevron（展開）とフォルダ名（スコープ選択）の2つ。スコープ中の行で「見えなくなる」のは chevron のみ
   （フォルダ名は accent 塗りの上の白文字で視認できる）であり、「フォルダを**開く**」という語も展開操作に対応する。
2. **常時の背景はスコープ中の行だけに付ける** — 全行に付けると 220px の狭い左ペインが視覚的に煩雑になり、
   design 2a の「静かなツリー」から離れる。問題が顕在化するのはスコープ中の行なので、そこだけ強調する。
   - ⚠️ 「全行で常に押せると分かるようにしたい」場合は承認時に指示してほしい。
3. **`scrollIntoView` の追従処理は共通フックへ切り出す** — `MovePanel` と `AddCurrentPanel` で同じ実装を2箇所に
   持つと、今回のような「片方だけ移植し忘れる」事故が再発する。1箇所に集約して両者から使う。
4. **本単位に新規のユニットテストは追加しない（追加できない）** — 変更対象が DOM 効果（`scrollIntoView`）と
   Tailwind のクラス指定のみで、切り出せる純粋ロジックが無い。プロジェクト方針（純粋ロジックのみテストし
   React コンポーネントのテストは持たない）に従い、**受け入れは実機確認で担保する**。
   既存テスト（`movePanelModel.test.ts` 等）が回帰していないことは品質ゲートで確認する。
