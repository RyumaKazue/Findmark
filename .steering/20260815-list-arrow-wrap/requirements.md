# 要件定義: list-arrow-wrap（LIST モードの ↑↓ 循環ナビゲーション）

- **作業単位名**: `list-arrow-wrap`
- **作成日**: 2026-08-15
- **指示元**: ユーザー指示「モードが LIST 状態の時に上下の矢印キーを押した時の挙動を修正して。一番上のアイテムにフォーカスが当たった時に ↑ が押された場合、一番下のアイテムにフォーカス。逆も然り。」
- **依存**: U8a focus-three-state ✅ / U7 popup-search-shell ✅（いずれも実装済み）

---

## 1. 概要

Popup の `LIST` モードにおける `↑` / `↓` の選択行移動を、**端でクランプ（何もしない）から端で循環（ラップアラウンド）へ変更する**。
先頭行で `↑` を押すと末尾行へ、末尾行で `↓` を押すと先頭行へフォーカスが移る。

## 2. 背景（何を解決するか）

現状の `Popup.tsx` は選択行の移動を以下のようにクランプしている:

```ts
case 'list:move-up':
  setSelectedIndex(i => Math.max(i - 1, 0));        // 先頭で押しても 0 のまま（無反応に見える）
case 'list:move-down':
  setSelectedIndex(i => Math.min(i + 1, lastIndex)); // 末尾で押しても最終行のまま
```

これは `docs/functional-design.md`「既定モードのキー挙動(フォーカス位置別)」の
「右ペイン(LIST): 選択行の移動(**端では何もしない**)」に忠実な実装だが、実使用上は以下の不都合がある:

- 検索結果が多いとき、末尾行を見るために `↓` を長押しする必要がある（`↑` 一発で末尾へ行けない）。
- キー入力に対して画面が一切変化しないため「キーが効いていない」と誤解される。

Findmark は「キーボードで完結する検索ポップアップ」を掲げており（`docs/ideas/keyboard-first-navigation.md`）、
候補リスト UI の一般的な作法（ランチャー系ツール・コマンドパレット）と同じく循環させるほうが一貫する。
本単位は**仕様（functional-design）ごと「端では循環」へ更新する**。

## 3. 実装対象

### 3.1 右ペインフォーカス時の `↑↓`（`list:move-up` / `list:move-down`）

- `listFocus === 'result'` で `↑` / `↓` を押したときの選択行移動を循環させる。

### 3.2 検索ボックスフォーカス時の `↑↓`（`list:leave-search-up` / `list:leave-search-down`）

- `listFocus === 'search'` の `↑↓` は「検索欄を離脱しつつ選択行を1つ動かす」挙動（U8a）。
  この1つ分の移動も**同じ循環規則に統一する**。
  - 例: 選択行が先頭（index 0）の状態で検索ボックスから `↑` → 右ペインへフォーカスが移り、選択行は末尾へ。
- 統一する理由は「解釈で埋めた点」#1 を参照。

### 3.3 ドキュメント（`docs/functional-design.md`）の更新

- キー挙動表の「右ペイン(LIST)」`↑↓` セルを「選択行の移動(端では何もしない)」→「選択行の移動(端で循環)」へ改める。
- 検索ボックス(LIST) の `↑↓` セルにも循環する旨を補記する。

## 4. 受け入れ基準

### AC-1: 右ペインでの `↑` が先頭から末尾へ循環する
- [ ] 結果が N 件（N ≥ 2）あり、選択行が先頭（index 0）・フォーカスが右ペインのとき、`↑` で選択行が末尾（index N-1）になる。
- [ ] 中間行での `↑` は従来どおり 1 つ上へ移動する。

### AC-2: 右ペインでの `↓` が末尾から先頭へ循環する
- [ ] 選択行が末尾（index N-1）・フォーカスが右ペインのとき、`↓` で選択行が先頭（index 0）になる。
- [ ] 中間行での `↓` は従来どおり 1 つ下へ移動する。

### AC-3: 検索ボックスからの `↑↓` も同じ循環規則に従う
- [ ] 選択行が先頭・フォーカスが検索ボックスのとき、`↑` で右ペインへフォーカスが移り選択行が末尾になる。
- [ ] 選択行が末尾・フォーカスが検索ボックスのとき、`↓` で右ペインへフォーカスが移り選択行が先頭になる。
- [ ] 検索ボックス離脱そのもの（`listFocus='result'` 化・`blur()`）の挙動は U8a から変わらない。

### AC-4: 境界条件で壊れない
- [ ] 結果が 0 件のとき、`↑↓` を押しても選択インデックスは 0 のまま（例外・NaN・負値にならない）。
- [ ] 結果が 1 件のとき、`↑↓` を押しても選択インデックスは 0 のまま（自分自身へ循環）。
- [ ] 結果件数の変化で選択インデックスが範囲外になっている場合でも、`↑↓` 後は必ず `0 <= index < N` に収まる。

### AC-5: 循環時にスクロールが追従する
- [ ] 先頭 → 末尾へ循環したとき、`ResultList` の仮想スクロールが末尾行まで追従して行が可視になる。
- [ ] 末尾 → 先頭へ循環したときも同様に先頭行が可視になる。
- [ ] （既存の「選択行が可視範囲外なら追従」ロジックで満たされることの確認で足りる。新規実装は不要見込み。）

### AC-6: 他モード・他 UI の `↑↓` は変更されない
- [ ] `FOLDER_TREE`（左ペイン）の `↑↓` は従来どおり端で何もしない（クランプ）。
- [ ] `ALIAS_EDIT` / `PANEL` / `AddCurrentPanel` の候補移動は変更しない。
- [ ] `INLINE_EDIT` / `DRAG` の `↑↓`（none）は変更しない。

### AC-7: 循環ロジックが純粋関数として単体テストされている
- [ ] インデックス移動の計算が React 非依存の純粋関数に切り出され、co-located なユニットテストを持つ。
- [ ] テストが AC-1〜AC-4 の条件（先頭/末尾/中間/0件/1件/範囲外）を網羅する。

### AC-8: 品質ゲート
- [ ] `pnpm test` / `pnpm lint` / `pnpm type-check` がフォアグラウンド実行で全て exit code 0。

### AC-9: ドキュメント整合
- [ ] `docs/functional-design.md` のキー挙動表が「端で循環」に更新されている。
- [ ] 変更理由（キーボード完結の一貫性）が同ドキュメント内で追える。

## 5. スコープ外

| 項目 | 理由 / 担当 |
|---|---|
| `FOLDER_TREE`（左ペイン）の `↑↓` 循環 | 今回の指示は LIST モード限定。左ペインは階層構造で「端」の意味が異なるため別途判断する |
| `PageUp` / `PageDown` / `Home` / `End` による一括移動 | 今回の指示範囲外 |
| `ALIAS_EDIT` / `PANEL` / `AddCurrentPanel` の候補リスト循環 | 今回の指示範囲外（挙動を揃えるかは将来判断） |
| 循環時の視覚的フィードバック（アニメーション等） | 過剰実装。スクロール追従で十分 |
| 選択行（複数選択・チェック）の挙動 | フォーカス移動と直交する独立状態のため変更しない |

## 6. 解釈で埋めた点（設計判断・**異論があれば計画承認時に指摘してほしい**）

1. **検索ボックスからの `↑↓`（`list:leave-search-*`）にも循環を適用する** — ユーザー指示は「LIST 状態の時の上下矢印」であり、
   LIST モードには検索ボックスフォーカスと右ペインフォーカスの2状態がある。同じ `LIST` 内で
   「右ペインからの `↑` は循環するが、検索ボックスからの `↑` はしない」という非対称は混乱を招くため、
   **両方に同じ規則を適用する**。
   - 特に「起動直後 = 選択行が先頭」の状態から `↑` 一発で末尾へ飛べるのは、循環を入れる主目的（末尾への到達性）に直結する。
   - ⚠️ ここを「右ペインのみ循環」に限定したい場合は承認時に指示してほしい。
2. **`FOLDER_TREE` は循環させない** — ユーザー指示が「LIST 状態の時」と明示しているため。
   左ペインは「すべて」行 + 可視フォルダ行という階層由来の並びで、末尾から先頭（＝「すべて」）へ飛ぶ意味が
   右ペインほど自明ではない。`Home` で「すべて」へ一発復帰できる代替手段もある。
3. **0件・1件のときは「無反応」で正しい** — 循環先が自分自身になるだけであり、特別扱いはしない。
4. **`docs/functional-design.md` を更新する（仕様変更として扱う）** — 現行の「端では何もしない」は
   意図的に書かれた仕様であり、実装だけ変えるとドキュメントと乖離する。仕様側を正として書き換える。
