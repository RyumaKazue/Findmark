# 要求内容 — U8a focus-three-state

## 概要

Popup のキーボードフォーカスを **検索ボックス / 右ペイン（ブックマーク一覧） / 左ペイン（フォルダツリー）の3状態**として明示的に管理し、`←→` でのペイン移動・`↑↓` での検索欄離脱・`Escape` の4段階戻りを成立させる。U8 で実装したモード状態機械（`modeMachine.ts`）に `FOLDER_TREE` モードと左ペインのキー意味論を追加する。

## 背景

キーボード完結ナビゲーションの仕様変更（`docs/ideas/keyboard-first-navigation.md`）により、フォーカスモデルが変わった。

**変更前（U8）**: フォーカスは検索ボックスに固定。`↑↓` は検索ボックスにフォーカスを置いたまま結果行の選択を動かす。左ペインはマウス専用。`Escape` は3段階（キーワードクリア → スコープ解除 → 閉じる）。

**変更後**: フォーカスは3箇所を行き来する。`↑↓` を押すと**検索欄からフォーカスが外れ、同時に選択行が1つ移動する**。右ペインで `←` → 左ペインへ、左ペインで `→` → 右ペインへ。`Escape` は「ペインにフォーカス → 検索ボックスへ戻る」が1段目に加わり4段階になる。

**検索ボックス内の `←→` はキャレット移動専用**とする点が設計の要。ペイン移動に奪うと `docs` と打って `doc` に直すというクエリ途中の修正ができなくなるため、`↑↓` を「検索欄を抜けるキー」に定めることで衝突を原理的に解消している。

## 実装対象の機能

### 1. `FOLDER_TREE` モードとフォーカス位置の型定義（modeMachine）
- `Mode` に `FOLDER_TREE` を追加する（`docs/development-guidelines.md` の `SearchMode` 型に整合）。
- `ListFocus`（`'search' | 'result'`）を追加する。LIST モード内のフォーカス位置を表す。
- `FocusArea`（`'search' | 'result' | 'folderTree'`）を追加し、`Mode` と `ListFocus` から導出する（`toFocusArea`）。Escape 段階戻りが参照する統合フォーカス位置。
- `ModeAction` に `ENTER_FOLDER_TREE` を追加し、`modeReducer` で LIST からのみ遷移を許可する（既存の防御的デフォルトに合わせる）。

### 2. フォーカス位置別のキー意味論（`resolveKeyIntent`）
- シグネチャを `resolveKeyIntent(mode, e, listFocus)` に拡張する。
- **検索ボックス（LIST + `search`）**: `↑↓` = 検索欄を離脱しつつ選択行を1つ移動 / `←→` = `none`（ネイティブのキャレット移動を温存）/ `Enter` = 選択行を開く / `Escape` = 段階戻り。
- **右ペイン（LIST + `result`）**: `↑↓` = 選択行の移動 / `←` = 左ペインへ / `→` = `none` / `Enter` = 選択行を開く / `Escape` = 段階戻り。
- **左ペイン（`FOLDER_TREE`）**: `↑↓` = フォルダ間移動 / `←` = 親フォルダへ / `→` = 右ペインへ / `Enter` = 展開トグル / `Home` = 「すべて」へ / `Escape` = 段階戻り。
- 追加インテント: `list:leave-search-up` / `list:leave-search-down` / `list:to-folder-tree` / `folder:move-up` / `folder:move-down` / `folder:parent` / `folder:to-result` / `folder:toggle-expand` / `folder:home`。
- 既存の `list:escape` を `escape:step-back` へ改名する（LIST と FOLDER_TREE が同じ段階戻りの梯子を共有するため、`list:` 接頭辞が実態と合わなくなる）。

### 3. Escape の4段階戻り（`resolveEscapeStep`）
- 既存 `resolveListEscape` を `resolveEscapeStep` へ改名し、文脈に `focusArea` を追加する。
- 段階: `focus-search`（左/右ペインにフォーカス）→ `clear-keyword`（キーワードあり）→ `clear-scope`（スコープが「すべて」以外）→ `close`。

### 4. Popup のフォーカス3状態の結線
- `listFocus` を Popup の state として保持する。
- `↑↓` で検索欄を離脱する際、**入力欄を `blur()` する**（キャレットを外し、以降 `←→` をペイン移動に使えるようにするため）。
- `←` / `→` でのペイン移動、`Escape` の4段階実行、検索ファースト復帰（左/右ペイン → 検索ボックス）を結線する。
- 左ペインにフォーカスがあることが分かる**視覚的フィードバック**を与える（Popup が組み立てる sidebar ノードにフォーカスリングを付ける。`FolderTree.tsx` 自体は変更しない）。

### 5. 検索ファースト復帰の対象確認
- `isSearchFirstExempt` に `FOLDER_TREE` を**含めない**（左ペインで印字文字を打つと検索ボックスへ復帰する）ことをテストで固定する。

## 受け入れ条件

> 出典: `docs/mvp-development-flow.md` U8a 行「受け入れ基準」。

### フォーカスの3状態と移動
- [ ] フォーカスが3箇所（検索ボックス / 右ペイン / 左ペイン）を `←→` / `↑↓` で行き来する。
- [ ] 検索ボックスで `↑↓` を押すと、検索欄からフォーカスが外れると同時に選択行が1つ移動する。
- [ ] 右ペインで `←` を押すと左ペインへフォーカスが移る。
- [ ] 左ペインで `→` を押すと右ペインへフォーカスが戻る。
- [ ] 左ペインにフォーカスがあることが視覚的に分かる。

### 検索ボックスのキャレット温存
- [ ] 検索ボックスにフォーカスがある間、`←→` は**キャレット移動専用**でペイン移動に使われない（クエリ途中を修正できる）。

### Enter の挙動
- [ ] `Enter` は検索ボックス・右ペインのどちらにフォーカスがあっても**選択行を開く**。
- [ ] 選択行は常に存在する（既定は先頭行）ため、`↑↓` を押さずに `Enter` だけで最短到達できる。

> **補足**: mvp-development-flow の受け入れ基準は「`Enter` がどのフォーカス位置でも選択行を開く」と記載しているが、PRD 機能6 / functional-design「既定モードのキー挙動」（いずれも本件の正）では **左ペインの `Enter` は展開/折りたたみトグル**である。本単位では左ペインの `Enter` を `folder:toggle-expand` インテントとして定義し、実行結線は U11 が担う（下記「スコープ外」参照）。

### Escape の4段階戻り
- [ ] `Escape` が4段階で1つずつ戻る（左/右ペインにフォーカス → 検索ボックスへ / キーワードあり → クリア / スコープが「すべて」以外 → 「すべて」へ / いずれでもない → 閉じる）。

### 検索ファースト復帰
- [ ] 左ペインで印字文字を打つと検索ボックスへフォーカスが復帰する。
- [ ] 右ペインで印字文字を打つと検索ボックスへフォーカスが復帰する。
- [ ] **（追加決定・2026-07-28）** 左ペイン・右ペインで修飾なしの `Backspace` を打っても検索ボックスへフォーカスが復帰する。ユーザーからのレビュー指摘により追加。「残っているクエリを消したい」という操作意図でも検索ボックスへ戻れるようにするため。

### 品質
- [ ] `modeMachine` の新しいキー意味論・遷移・段階戻りがユニットテストで固定されている。
- [ ] `pnpm test` / `pnpm lint` / `pnpm type-check` がエラーなく通る。

## 成功指標

- `modeMachine.test.ts` が、フォーカス3状態それぞれのキー意味論と4段階 Escape を網羅的に固定している。
- 既存テスト（モード遷移・印字判定・ショートカット解決）に回帰がない。
- マウス操作（📎 フォルダ選択ボタン、行クリック）が従来どおり動作する。

## スコープ外

以下はこのフェーズでは実装しません:

- **左ペイン内の実際のナビゲーション動作** → **U11**
  - `↑↓` でどのフォルダにフォーカスが当たるか（フォーカス中フォルダの状態管理）
  - フォーカス移動に伴う**スコープ追従**（右ペインの切り替え）
  - `←`（親フォルダへ）・`Enter`（展開トグル）・`Home`（「すべて」へ）の**実行結線**
  - 本単位はこれらを `modeMachine` の**インテントとして定義するまで**を担う（U8 が INLINE_EDIT / PANEL / DRAG のインテントのみ定義し UI 実体を U9/U10/U12 に委ねた先例に倣う）
- **`FolderTree.tsx` / `FolderTreeItem.tsx` の変更** → U11（`docs/mvp-development-flow.md` の U8a「主な対象領域」は `modeMachine.ts` / `useMode.ts` / `Popup.tsx` の3ファイル）
- **フォルダチップのスコープ可視化表示** → U11
- **`Ctrl/Cmd+Enter`（新規タブで開く）** → 現状どおり `none` に倒す。U8a の受け入れ基準に含まれず、`BookmarkService.openUrl` も新規タブ引数を持たないため、対応単位で別途扱う
- **展開状態の永続化・多階層省略** → U11
- **起動時の既定フォーカスを左ペインにすること** → **U11**
  - 2026-07-28 の追加決定で、起動時の既定フォーカスは左ペインになった（PRD 機能1/6）。ただし左ペインがキーボードで操作可能になるのは U11 であり、本単位で先に既定値を変えると `↑↓` が何も起こさないペインへ着地する。よって本単位の初期値は暫定的に `LIST` + `listFocus='search'` のままとし、U11 が左ペイン操作の実装と同時に既定値を切り替える。
- **保存状態の復元（フォーカス位置・スコープ・選択ブックマーク・クエリ）** → **U19 `popup-state-restore`**（PRD 機能13）
- **インライン編集 / フォルダ選択パネル / D&D のモード実体** → U10 / U12
