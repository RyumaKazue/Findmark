# 要件定義: U11 folder-scope-tree（フォルダスコープ / 左ペインツリー）

- **作業単位ID / 名**: U11 / `folder-scope-tree`
- **対応MVP機能**: 機能5（フォルダスコープ: 左ペインと右ペインの連携）
- **依存**: U4 bookmark-service ✅ / U7 popup-search-shell ✅ / U6a search-scope-revision ✅ / U8a focus-three-state ✅
- **作成日**: 2026-07-28
- **指示元**: [docs/mvp-development-flow.md](../../docs/mvp-development-flow.md)「作業単位一覧」U11 行

---

## 1. 目的（何を解決するか）

U7 で作った左ペイン FolderTree は「表示 + 📎ボタンによるクリック選択」に留まり、**キーボードから一切到達できない**。
U8a で `FOLDER_TREE` モードとキー意味論（`↑↓`/`←`/`→`/`Enter`/`Home`）は定義済みだが、**実行結線は U11 に持ち越されている**
（`Popup.tsx` の `folder:*` インテントは `return` のみ）。

本単位は左ペインを**キーボード操作可能なスコープ選択面**にし、
「常にどれか1つのフォルダにスコープが当たり、フォーカス移動とともに右ペインが追従する」方式を完成させる。
あわせて U7 時点の暫定実装（📎フォルダ選択ボタン）を廃止し、マウス操作とキーボード操作が
**同じスコープ状態を更新する**構造へ再設計する（2026-07-28 決定）。

## 2. 受け入れ基準

`docs/mvp-development-flow.md` U11 行「受け入れ基準」を写し取り、検証可能な粒度へ分解する。
引用元: PRD 機能5 / 機能6（[product-requirements.md](../../docs/product-requirements.md)）、
functional-design「既定モードのキー挙動(フォーカス位置別)」「UI設計 > 全体レイアウト」（[functional-design.md](../../docs/functional-design.md)）、
design README 1a/1b/2a/2b・Interactions & Behavior（[design/README.md](../../docs/design/README.md)）。

### AC-1: スコープは常に1つ存在し、既定は「すべて」
- [ ] 左ペインには常にどれか1つ（「すべて」を含む）にスコープが当たっており、「選択なし」状態が存在しない。
- [ ] 起動直後のスコープは「すべて」（= `scopeFolderId === null`）。
- [ ] スコープが当たっているフォルダは左ペインで accent 塗り + 白文字でハイライトされる（design 1b/2a）。
- [ ] スコープ設定時、その**祖先フォルダ（自身は含まない親チェーン）を自動展開**し、スコープ中フォルダを可視にする（PRD 機能5）。
      **スコープ中フォルダ自身は展開しない**（子の展開は `Enter`／三角クリックのみ。フォーカス=スコープと展開を分離する）。
      ※キーボード操作では `↑↓`/`←` が可視行しか辿らないため、この自動展開は実質 U19（保存復元）で意味を持つ安全弁。

### AC-2: 左ペインの `↑↓` でスコープが追従し右ペインが切り替わる
- [ ] `↑↓` は「すべて」行 + 展開中のフォルダ行からなる**可視行**を1つずつ移動する。
- [ ] 移動と同時にスコープが追従し、右ペインの内容が即座に切り替わる（selection follows focus）。
- [ ] 端（先頭/末尾）では何もしない。
- [ ] スコープ変更時、右ペインの選択行は先頭へ戻る。

### AC-3: `←` 親へ / `→` 右ペインへ / `Enter` 展開トグル / `Home` 「すべて」へ
- [ ] `←`: 親フォルダへ移動しスコープも親へ。最上位フォルダ・「すべて」では何もしない。
      **最上位フォルダ = 真のルート直下のフォルダ（現状はブックマーク バー等）。親を持たない（`findParentId` が `null`）ため `←` は no-op**。
      「すべて」へは `←` では到達せず、`Home`／`Escape` 段階戻りで戻る。なお `↑`（可視行移動）では最上位フォルダの直上の「すべて」行へ移動できる（`←` とは別経路）。
- [ ] `→`: 右ペイン（LIST + `listFocus='result'`）へフォーカスが移る（U8a 実装済みの経路を維持）。
- [ ] `Enter`: フォーカス中フォルダの展開/折りたたみをトグルする。子を持たないフォルダ・「すべて」行では何もしない。
- [ ] `Home`: スコープを「すべて」へ一発で戻し、フォーカスも「すべて」行へ移る。

### AC-4: 起動時の既定フォーカスが左ペインになる
- [ ] 起動直後のモードが `FOLDER_TREE`（= 左ペイン）になり、U7 の「検索ボックスへ自動フォーカス」は廃止される。
- [ ] 左ペインに実 DOM フォーカスが当たり、`↑↓` が即座に効く。
- [ ] 印字文字または修飾なし `Backspace` で検索ボックスへ復帰する（U8a の検索ファースト復帰を維持）。
- [ ] 起動→操作可能まで 200ms 以内（索引構築の完了を待たない）。
- [ ] 保存状態からの復元は本単位のスコープ外（U19）。

### AC-5: 「すべて」は全件・それ以外は直下のみ
- [ ] スコープ「すべて」= 全ブックマークが対象（クエリ空はタイトル昇順）。
- [ ] スコープがフォルダ = **当該フォルダの直下のみ**。サブフォルダは含めない。クエリの有無で範囲は変わらない。
- [ ] （U6a 実装済みの `SearchQuery.folderScope` 経由。本単位で検索ロジックは変更しない。）

### AC-6: フォルダパスは照合対象外 / `/` 含みでも壊れない
- [ ] スコープは検索語の照合対象にならない（絞り込み範囲としてのみ作用する）。
- [ ] スコープはフォルダ **ID** で保持する。フォルダ名に `/` が含まれてもスコープ・パス表示が壊れない
      （パスは配列で保持し、表示時にのみ ` / ` で結合する）。

### AC-7: チップはスコープ可視化のみで操作主体ではない
- [ ] スコープが「すべて」以外のとき、検索ボックス先頭に `📁 開発 / chrome` 形式のフォルダチップが表示される（design 1b）。
- [ ] チップは表示専用で、クリック等でスコープを操作する手段を持たない。
      解除は `Escape` の段階戻り、「すべて」への復帰は `Home` が担う。
- [ ] 深い階層ではパスを圧縮する（先頭1階層 + `…` + 末尾2階層。深さ4以下は圧縮しない。design 2b）。

### AC-8: 展開三角とフォルダ名クリックが分離され📎ボタンが存在しない
- [ ] 行内の押下対象が2つに分離される: **(1) 展開三角 = 展開/折りたたみ専用** / **(2) 「📁 フォルダ名」= スコープ選択**。
- [ ] 三角は `▸`/`▾` の素の記号ではなく、押下可能と分かる見た目（ホバー背景を持つボタン + chevron アイコン）にする。
- [ ] `FolderSelectChip`（📎）がコードベースから削除されている。
- [ ] マウスクリックとキーボード操作が**同じスコープ状態**（`scopeFolderId`）を更新し、二重管理にならない。
- [ ] クリック後も内部フォーカスモデルと実 DOM フォーカスが一致する（U8a からの持ち越し課題の解消）。

### AC-9: 子なしフォルダも名前クリックでスコープ選択できる
- [ ] 子フォルダを持たないフォルダの「📁 フォルダ名」部分が押下可能で、押下でスコープになる
      （U7 では非ボタンの `<span>` だった）。

### AC-10: 展開状態の永続化
- [ ] 展開/折りたたみが `chrome.storage.local`（`LocalState.expandedFolderIds`）へ永続化され、次回起動時に復元される。
- [ ] 初回起動（永続値なし）では最上位フォルダが展開された状態になる。
- [ ] 「すべて畳んだ」状態が次回起動時に復元される（初回既定と区別できる）。

### AC-11: 多階層フォルダツリー（design 2a / 2b）
- [ ] 3〜4階層のツリーがインデントガイド線付きで破綻なく表示される（2a）。
- [ ] 深い階層（第4階層以降）はインデントを詰める（2b）。
- [ ] 深さ5以上の子リストは先頭2件で打ち切り、残りを「さらに N 件…」で示す（design README「State Management」）。
      「さらに N 件…」は `Enter`/クリックで残りを表示でき、キーボードから到達できる。
- [ ] フォルダ名は省略せず、見切れる場合は横スクロールで全表示する（U7 の方針を維持）＋全文ツールチップ。

### AC-12: スコープの可視化（右ペインのメタ行）
- [ ] 右ペイン上部にメタ行（height 34）を出し、現在のスコープと件数を示す（design 1b/2a）。
  - クエリあり: `{パス} の中から「{クエリ}」— N件`
  - クエリなし & スコープあり: `{パス} の直下 — N件`
  - クエリなし & スコープ「すべて」: メタ行を出さない（design 1a にメタ行がないため）
- [ ] パスは AC-7 と同じ圧縮規則を適用する。

### AC-14: アクティブペインの視覚的区別（相互アクセント + ペイン枠）（2026-07-28 追加・ユーザー指摘）

左ペイン（フォルダ）と右ペイン（結果リスト）の**どちらにキーボードフォーカスがあるか**を、色で直感的に把握できるようにする。フォーカス位置は `toFocusArea(mode, listFocus)` の `folderTree` / `result` / `search` で判定する。

- [ ] **相互アクセント**: アクティブなペインの選択/スコープは accent 濃色で強調し、非アクティブなペインの選択/スコープは淡いグレー系に落とす。
  - 左ペインがアクティブ（`folderTree`）: スコープ中フォルダ = accent 塗り + 白文字（強）。非アクティブ時 = accent 淡背景 + accent 文字（弱）。
  - 右ペインがアクティブ（`result`）: 選択行 = accent 淡背景 + accent 左バー（強）。非アクティブ時 = 中立グレー選択背景（弱）。
- [ ] **ペイン枠**: アクティブなペイン全体に focus ring（クリップされない inset 方式）を出す。左右で対称に適用する。
- [ ] 検索ボックスがアクティブ（`search`）のときは両ペインとも弱表示にし、検索ボックス自身の focus ring で位置を示す（既存動作を維持）。
- [ ] フォーカス移動（`←→` / クリック / モード遷移）に追従して即座に強弱が入れ替わる。

### AC-13: 品質ゲート
- [ ] 追加した純粋ロジックにユニットテストがある（可視行フラット化・親解決・祖先収集・パス圧縮・メタ行文言）。
- [ ] `pnpm test` / `pnpm lint` / `pnpm type-check` が全てパスする。

## 4. 解釈で埋めた点（設計判断）

ドキュメントに明記がなく、合理的な解釈で埋めた項目。**異論があれば計画承認時に指摘してほしい。**

1. **フォルダチップの `✕` を出さない** — design 1b はチップ右端に `✕` を描いているが、
   PRD 機能5・functional-design は「チップは操作主体ではない」と定めている。押せない `✕` はむしろ誤誘導になるため、
   **`✕` は描画しない**（design からの意図的逸脱として `docs/functional-design.md`「デザイン非採用項目」へ追記する）。
2. **「さらに N 件…」行のフォーカス時はスコープを変更しない** — この行はフォルダではないため、
   フォーカスが乗ってもスコープは直前のまま保持する（`Enter` で残りを表示する展開トグルの一種として扱う）。
   「展開中の**フォルダ**間を移動（スコープが追従）」という仕様文言とは矛盾しない。
   展開状態と異なり、この「残りを表示」状態は**永続化しない**（ポップアップを開くたびリセット）。
3. **design 2b の「階層をたたむ ▴」固定バーは実装しない** — 全折りたたみは `←` の連打・`Home` で代替でき、
   220px の縦領域を常時 34px 消費するコストに見合わない。実装しない旨を design 非採用項目へ追記する。
4. **`←` は最上位フォルダで「すべて」へは移動しない** — functional-design「親フォルダへ移動(最上位では何もしない)」に忠実に従う。
   「すべて」へは `Home` / `Escape` 段階戻りで到達する。
5. **右ペインのメタ行を U11 に含める** — design 1b/2a がメタ行を含み、両状態とも U11 に割り当てられているため。
