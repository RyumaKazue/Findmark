# 要求内容 — folder-scope-descendants（フォルダスコープを配下すべてへ）

## 概要

左ペインでフォルダを選んだときの右ペインの表示対象を、**そのフォルダの直下のみ**から**配下すべて（サブフォルダの中身を含む）**へ変更する。ブラウズ時（クエリなし）は**直下のブックマークをサブフォルダ内のものより上**に並べる。

## 背景

現在の仕様は「スコープ＝そのフォルダの**直下のみ**」で、サブフォルダの中身は表示されない（`SearchEngine.inScope` が `entry.node.parentId === scope.folderId` で判定）。これは PRD 機能5・functional-design の「デザイン非採用項目 #4」で明示的に選ばれた仕様だが、実際に使うと次の問題がある。

- **フォルダを選んでも中身が見えない**。`開発` を選んでも、実際のブックマークが `開発/chrome` や `開発/aws` に入っていれば右ペインは空に近くなる。目的のものに辿り着くには、どのサブフォルダにあるかを覚えていて、そこまで降りる必要がある。
- **左ペインの件数バッジと右ペインの件数が食い違う**。ツリーの件数は `countDescendants`（配下すべて）で数えているのに、右ペインは直下しか出さない。「12件」と表示されているフォルダを選んで2件しか出ない、という状態が起きる。
- 「直下のみ」の運用は、`Escape` で「すべて」へ戻ってから検索し直す導線で補う設計だったが、**フォルダを見るという操作の自然さを損なっている**。

本単位はこの仕様判断を見直し、「フォルダを選ぶ＝そのフォルダ以下を見る」という一般的な期待に合わせる。あわせて**直下を上に置く**ことで、「このフォルダに直接入れたもの」を見失わないようにする。

  - PRD 機能5「フォルダスコープ」— **本単位で受け入れ条件を改訂する**
  - `docs/functional-design.md`「デザイン/初期案からの変更点」#4（「直下のみ」の採用）— **本単位で再改訂する**
  - `packages/shared/lib/search/SearchEngine.ts`（`inScope` / `sortResults`）

## 決定事項（本要求の作成時にユーザーと確定）

| # | 論点 | 決定 |
|---|---|---|
| 1 | スコープの対象範囲 | **配下すべて**（サブフォルダの中身を含む） |
| 2 | 直下の優先表示 | **ブラウズ時（クエリなし）のみ**直下を上に置く。**検索時（キーワードあり）は関連度（スコア）順**のまま |
| 3 | 深さの扱い | **2段階**（「直下」と「それ以外の配下すべて」）。孫・ひ孫の間では従来の並び（スコア → タイトル昇順）を保つ |

**決定事項2の理由**: 検索時に階層を優先すると、深い階層にある強い一致（別名の完全一致など）が、直下の弱い一致（タイトルの部分一致）の下に埋もれる。検索は「関連度で見つける」操作であり、階層は二の次であるべき。一方ブラウズは「このフォルダを見る」操作なので、直下が上に来るほうが構造と一致する。

## 実装対象の機能

### 1. スコープ判定の変更（`SearchEngine`）

- `inScope` を「直下のみ」から「**そのフォルダ自身の配下すべて**」へ変更する。
- 索引エントリは現在フォルダ名のパス（`folderPath`）しか持たず、**ID による祖先判定ができない**。索引構築時に**フォルダ ID のパス**を併せて保持する。
  - 名前ではなく ID で判定する（同名フォルダが別階層にあっても取り違えない。フォルダ名に `/` を含んでも壊れない、という既存方針と同じ理由）。

### 2. ブラウズ時の並び（`SearchEngine`）

- クエリが空のとき、**直下のブックマークを先頭グループ**に、**それ以外の配下を後続グループ**に置く。各グループ内は従来どおりタイトル昇順。
- クエリがあるときは**従来どおりスコア降順 → タイトル昇順**（グループ分けをしない）。
- スコープ「すべて」（未指定）のときは従来どおり（直下という概念が無いため、全件をタイトル昇順）。

### 3. メタ行の文言（`resultMetaModel` / i18n）

- クエリなし・スコープありのメタ行は現在「`開発 / chrome の直下 — 5件`」。表示範囲が変わるため「**配下**」を表す文言へ改める。
- クエリありの文言（「`〜 の中から「docs」— 4件`」）は範囲を限定していないため変更しない。

### 4. 影響範囲の確認（変更しないもの）

- **フォルダパスの行内表示**は既存のまま。配下表示になることで各行のパスが「どのサブフォルダにあるか」を示す実用的な情報になる（従来はスコープ時に全行同じパスで冗長だった）。
- **左ペインの件数バッジ**は変更しない（既に配下すべてを数えており、本変更で右ペインと一致するようになる）。
- 移動（`MovePanel` / D&D）・削除・別名編集・複数選択・ゴミ箱は影響を受けない。

## 受け入れ基準

- [ ] **AC-1（配下すべてを表示）**: サブフォルダを持つフォルダを選ぶと、直下のブックマークに加えて**サブフォルダ内のブックマークも表示**される。
- [ ] **AC-2（直下が上・ブラウズ時）**: クエリが空のとき、直下のブックマークがサブフォルダ内のものより**すべて上**に並ぶ。各グループ内はタイトル昇順。
- [ ] **AC-3（深さは2段階）**: 孫・ひ孫のブックマーク同士は深さで区別されず、従来の並び（タイトル昇順）で並ぶ。
- [ ] **AC-4（検索時はスコア順）**: キーワード入力中は階層に関係なく関連度順に並ぶ（深い階層の強い一致が直下の弱い一致より上に来る）。
- [ ] **AC-5（ID で判定）**: 同名のサブフォルダが別階層に存在しても、選んだフォルダの配下だけが表示される。
- [ ] **AC-6（「すべて」は不変）**: スコープが「すべて」のときの表示・並びは従来どおり。
- [ ] **AC-7（件数の一致）**: 左ペインのフォルダ件数バッジと、そのフォルダを選んだときの右ペインの件数が一致する。
- [ ] **AC-8（メタ行）**: クエリなし・スコープありのメタ行が、配下すべてを対象としていると分かる文言になっている。
- [ ] **AC-9（既存機能の非退行）**: 検索・別名マッチ・フォルダ名マッチ・あいまい一致フォールバック・移動・削除・複数選択・状態復元がすべて従来どおり動く。
- [ ] **AC-10（品質ゲート）**: `pnpm test` / `pnpm lint` / `pnpm type-check` が通る。スコープ判定とブラウズ時の並びにユニットテストがある。

## 成功指標

- フォルダを選んだときに「そのフォルダに入れたもの」が階層を降りずに一覧できる。
- 左ペインの件数と右ペインの件数が常に一致する（現在の食い違いが解消される）。

## スコープ外

- 「直下のみ / 配下すべて」を切り替えるオプションの追加（**常に配下すべて**にする。切り替えは設定項目を増やすだけで、どちらを選ぶべきかの判断をユーザーに押し付ける）。
- サブフォルダごとの見出し（グループ区切り）の表示。並び順のみで表現する。
- 左ペインの件数バッジの仕様変更（既に配下すべてで正しい）。
- 検索時のスコアリング規則の変更（フォルダ深さをスコアに加味する等）。
