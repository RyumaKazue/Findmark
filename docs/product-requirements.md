## プロダクト概要

### 名称
**Findmark** - 別名で探せるブックマーク検索拡張機能

### プロダクトコンセプト
- **自分だけの別名(エイリアス)で探せる**: 辞書や自動変換に頼らず、ユーザーが付けた別名で検索精度を上げる。英語タイトルのサイトを `kakuchou` のような自分の呼び名で一発で引ける
- **キーボードだけで完結する操作体系**: 起動・検索・フォルダ移動・ブックマーク選択・整理のすべてを、マウスに持ち替えずに到達できる。検索ボックス / ブックマーク一覧 / フォルダツリーの3領域を矢印キーだけで行き来し、**キーボード操作を最優先に据える**。検索とフォルダのブラウズは対立するものではなく、同じキーボード操作体系の上で連続的につながる
- **別名ごと持ち運べる独自エクスポート**: 別名などの独自メタデータを含めて持ち出せるJSON形式を差別化の核とし、別アカウント・別PCへの完全移行を可能にする

### プロダクトビジョン
ブックマークは「後で使うために保存する」ものだが、実際には「保存したことを忘れる」「探せない」ために死蔵されがちである。Findmarkは、ユーザー自身が付けた別名(略称・読みがな・英語名・自分だけの呼び名)を検索キーにすることで、この「探せない」問題を根本から解決する。外部通信ゼロ・host permission不要のクリーンな権限構成を維持し、「データ収集なし」を技術的に保証する。Chrome標準のブックマーク機能を置き換えるのではなく、その上に「検索して使う」レイヤーを重ねることで、既存の資産をそのまま活かす。

### 目的
- ユーザーが保存したブックマークを、記憶している任意の呼び名から数秒で見つけられるようにする
- 検索結果の場でリネーム・移動・削除・別名編集を完結させ、整理のためのコンテキストスイッチをなくす
- 別名を含む独自フォーマットでの移行手段を提供し、環境を移ってもユーザーの資産(別名の蓄積)が失われないようにする
- 外部通信ゼロを維持し、プライバシーを技術的に担保する

## ターゲットユーザー

### プライマリーペルソナ: 佐藤健(32歳、Webエンジニア)
- **基本属性**: 事業会社のフロントエンドエンジニア、実務経験8年
- **技術スタック**: Chrome常用、複数プロジェクトのドキュメント・記事・ツールを日常的にブックマーク。キーボード操作を好み、マウスへの持ち替えを嫌う
- **現在の課題**:
  - ブックマークが数百件あり、Chrome標準のフォルダ階層では目的のものに辿り着けない

  - 検索してもタイトル完全一致でしか出ず、うろ覚えのキーワードでは見つからない
- **期待する解決策**: 自分の言葉(別名)で引ける検索と、見つけたその場で整理できる操作性
- **1日の典型的なワークフロー**: 開発中に何度もドキュメントを参照。「あの記事どこだっけ」を1日に何度も繰り返し、そのたびに検索・スクロールで時間を溶かしている

### セカンダリーペルソナ: 鈴木優(27歳、リサーチャー)
- **基本属性**: 情報収集を主業務とし、日々大量のURLをブックマーク
- **現在の課題**: 保存はするが分類が追いつかず「未整理」フォルダが肥大化。後から探せず死蔵している
- **期待する解決策**: 分類しなくても別名とインクリメンタル検索で拾える仕組み。複数選択での一括整理

## 前提条件・対象環境

### 対応ブラウザ
- **Chrome(Manifest V3対応版)を対象とする**。MVPはChrome専用。
- Firefox 対応は将来検討(Post-MVP)。`favicon` 権限・sidePanel 等の差異があるため、MVPスコープには含めない。
- Safari・その他ブラウザは対象外。

### 別名同期の前提(重要)
- 別名データは `chrome.storage.sync` に保存され、**Chromeにサインインし同期が有効な場合にのみ端末間で自動同期される**。
- **非サインイン時 / 同期無効時は、当該端末内(local相当)にのみ保存される**。この状態でも拡張機能は完全に動作するが、別のPCへ別名は自動反映されない。
  - この場合の移行手段として、独自JSONのエクスポート/インポート(機能11)を提供する。
- **別アカウント・別プロファイルへの移行は自動同期の対象外**であり、独自JSONのエクスポート/インポートで引き継ぐ(手動)。
- UI要件: 同期が無効な環境では、別名がこの端末のみに保存される旨を必要に応じて示す(詳細は functional-design.md で定義)。

## 成功指標(KPI)

> **測定の大原則**: 本プロダクトは外部通信ゼロ・データ収集なしを掲げるため、**テレメトリによる利用状況の自動計測は一切行わない**。したがってKPIは「テレメトリなしで検証できる指標」に限定する。母集団全体の行動比率(利用率・継続率など)はテレメトリなしでは技術的に測定不能なため、**定量目標(KPI)としては採用せず**、後述の「定性的な観測目標」として小規模なオプトイン調査で傾向を把握するにとどめる。この割り切りはプロダクトの信頼性の一部として受容する。

### プライマリーKPI(テレメトリなしで検証可能)
- **検索到達時間**: ポップアップ起動から目的のブックマークを開くまで平均5秒以内
  - 測定: 初見〜習熟ユーザー各5名程度のタスク型ユーザビリティテスト(10件規模の結果表示を想定)
- **Chrome Web Store 評価**: 平均4.0以上(レビュー20件以上時点)
  - 測定: Chrome Web Store の公開評価・レビュー
- **クラッシュ/致命的バグ報告**: 主要導線(検索・開く・別名編集・移動・削除)で致命的バグ報告ゼロ
  - 測定: ストアレビュー・GitHub Issue の内容分類

### セカンダリーKPI(公開統計で検証可能)
- **累計インストール数 / 週間アクティブユーザー**: Chrome Web Store デベロッパーダッシュボードの公開統計で継続的にモニタリング(具体目標はリリース後の初期実績を基準に設定)
- **アンインストール率**: ダッシュボードのインストール/アンインストール推移から傾向を把握

### 定性的な観測目標(KPIではない・オプトイン調査で傾向把握)

以下は「そうなってほしい」方向性であり、テレメトリで自動検証はできない。四半期に1回程度、**N=10〜20名の任意参加インタビュー/アンケート**で定性的に傾向を確認する(自動送信は行わない)。

- 別名を積極的に活用しているか(別名機能が価値の中核として使われているか)
- ポップアップを開いたら実際に検索して目的を達成できているか
- 環境移行時に独自JSONエクスポートで別名を持ち運べたか

> **注**: リリース前は上記のうち「検索到達時間」を最重要の受け入れ基準とする。利用率・継続率のような母集団統計を定量KPI化したい場合は、外部通信ゼロ原則を維持したまま**明示的オプトインの集計送信**を別途設計し、architecture.md / functional-design.md に反映する必要がある(現時点ではスコープ外)。

## 機能要件

### コア機能(MVP)

#### 1. 検索ポップアップ(基盤)

**ユーザーストーリー**:
ブックマークを頻繁に参照するユーザーとして、キーボードから手を離さずに目的のブックマークへ辿り着くために、起動と同時にキーボード操作を始められるインクリメンタル検索ポップアップが欲しい

**受け入れ条件**:
- [ ] 拡張機能アイコンのクリック、またはキーボードショートカットで起動する
- [ ] 起動時のフォーカス位置は、**保存された状態があればそれを復元**し、無ければ**左ペイン(フォルダツリー)**とする(機能6・機能13)
- [ ] どのフォーカス位置から起動しても、**印字文字または Backspace を打てば検索ボックスへ復帰**して検索を開始できる(機能6)
- [ ] 入力1文字ごとに結果が絞り込まれる(インクリメンタル検索)
- [ ] ブックマーク一覧の選択行は**常に存在する**(既定は先頭行)。検索ボックスにフォーカスがある間も選択行はハイライトされる
- [ ] `Enter` はフォーカス位置に関係なく選択行を現在タブで開く。`Ctrl/Cmd+Enter` で新規タブ。クリックでも開ける
- [ ] `↑↓` で選択行を移動する。検索ボックスにフォーカスがある状態で押した場合は、**検索ボックスからフォーカスが外れると同時に**選択行が1つ移動する
- [ ] 検索対象は「タイトル + フォルダ名 + 別名」の3つである
- [ ] ポップアップは最大 800×600px に収まる

**優先度**: P0(必須)

#### 2. 検索マッチング(正規化)

**ユーザーストーリー**:
うろ覚えのキーワードで検索するユーザーとして、表記ゆれや大小文字を気にせず引っかけるために、正規化されたAND部分一致検索が欲しい

**受け入れ条件**:
- [ ] スペース区切りの複数ワードをAND条件で部分一致検索する
- [ ] 検索語・被検索文字列の両方に正規化を適用する(大文字小文字を区別しない / `String.normalize('NFKC')` で全角半角統一 / ひらがな・カタカナを同一視)
- [ ] 結果ゼロ時にタイポ耐性のあるフォールバック(あいまい一致)を行う
- [ ] ローマ字・読みがな一致は別名登録によって実現する方針とし、辞書は同梱しない

**優先度**: P0(必須)

#### 3. 別名(エイリアス)の登録・編集

**ユーザーストーリー**:
英語タイトルのサイトを日本語で探したいユーザーとして、自分だけの呼び名で引けるようにするために、1件のブックマークに複数の別名を付けられる機能が欲しい

**受け入れ条件**:
- [ ] 1件のブックマークに複数の別名を登録できる(チップUI)
- [ ] 入力後 Enter / `,` / Space でチップ確定、入力欄が空のときの Backspace で直前チップ削除、チップの `×` で削除、チップクリックで再編集
- [ ] 正規化後に比較して重複を自動で弾き、弾いた際は既存チップを一瞬光らせる
- [ ] 1件あたり最大20個、1個あたり最大50文字の上限を課す
- [ ] 検索でマッチした別名は結果行の先頭にハイライト付きで必ず表示する(省略対象から除外)

**優先度**: P0(必須)

#### 4. その場で編集・整理

**ユーザーストーリー**:
検索して見つけたユーザーとして、別画面に移らず整理を済ませるために、結果行から直接リネーム・URL編集・移動・削除ができてほしい

**受け入れ条件**:
- [ ] 各結果行からリネーム / URL編集 / フォルダ移動 / 削除ができる
- [ ] リネーム・URL編集はインライン編集(モーダルなし)で、タイトルとURLを同時に展開表示する
- [ ] フォーカスアウト時は「確定」、破棄はEscapeの明示操作のみ(ポップアップが閉じる事故で入力が消えるのを防ぐ)
- [ ] URL不正時は赤枠で確定不可とし、エラーを行の下にインライン表示する
- [ ] 削除は即時アンドゥ付き(トーストで5秒間取り消し可能)
- [ ] 「保存ボタンで確定」型モーダルを使わず、即時保存 + アンドゥで統一する

**優先度**: P0(必須)

#### 5. フォルダスコープ(左ペインと右ペインの連携)

**ユーザーストーリー**:
特定フォルダ内に絞って探したいユーザーとして、マウスに持ち替えずにフォルダを辿るために、左ペインのフォルダツリーをキーボードで移動でき、その中身が即座に右ペインへ反映される仕組みが欲しい

**受け入れ条件**:
- [ ] **常にどれか1つのフォルダにスコープが当たっており**、その中身が右ペインに表示される。起動時のスコープは**既定で「すべて」**とし、保存された状態があればそれを復元する(機能13)
- [ ] 左ペインでフォーカスを移動すると、**移動と同時にスコープが追従**して右ペインの内容が切り替わる
- [ ] 「すべて」にスコープがあるときは**例外的に全ブックマークを表示**し、検索時も全件を対象とする(並び順はクエリ空時はタイトル昇順。「最近順」は採用しない)
- [ ] 「すべて」以外にスコープがあるときは、**そのフォルダ直下のブックマークのみ**を対象とする。クエリが空のとき(ブラウズ)も、クエリがあるとき(検索)も同じ
- [ ] 「サブフォルダを含む」という指定は設けない(「直下のみ」か「すべて」かの2択)
- [ ] フォルダスコープはキーボードのみで到達・解除できる(操作の詳細は機能6)
- [ ] 検索ボックス先頭のフォルダチップ(例 `📁 開発/chrome`)は、**現在のスコープを可視化する表示要素**とする。チップ自体はスコープを操作する主体ではない
- [ ] スコープが当たっているフォルダは左ペインでハイライトし、親フォルダを自動展開する
- [ ] フォルダパスは検索語の照合対象から除外する(スコープは絞り込み範囲であり検索語ではない)
- [ ] 内部的にフォルダIDを保持し、フォルダ名に `/` が含まれても壊れない

> **深いフォルダで検索がヒットしない場合の導線**: 直下のみを厳格に適用するため、目的のフォルダに辿り着いていないと検索がヒットしない。この場合は「すべて」へ戻ってから検索する運用とし、機能6 の `Escape` 段階戻りと左ペインの `Home` が復帰手段を担保する。

**優先度**: P0(必須)

#### 6. フォーカス移動とキーボード操作

**ユーザーストーリー**:
キーボード中心で操作するユーザーとして、マウスに持ち替えず全操作を完結できるように、3領域を行き来するフォーカス移動と、衝突のない一貫したキー割り当てが欲しい

**受け入れ条件**:

*フォーカス3状態*
- [ ] フォーカスは **検索ボックス / 右ペイン(ブックマーク一覧) / 左ペイン(フォルダツリー)** の3箇所を行き来する。起動時は**既定で左ペイン**とし、保存された状態があればそれを復元する(機能13)
- [ ] 検索ボックスでは `←→` は**キャレット移動専用**とし、ペイン移動には使わない(クエリの途中を修正できることを担保する)
- [ ] 検索ボックスで `↑↓` を押すと、検索ボックスからフォーカスが外れると同時に選択行が1つ移動する
- [ ] 右ペインで `←` を押すと左ペインへ、左ペインで `→` を押すと右ペインへフォーカスが移る
- [ ] 左ペインで `←` は親フォルダへ移動する(最上位では何もしない)
- [ ] 左ペインで `Enter` は展開/折りたたみのトグル、右ペイン・検索ボックスで `Enter` は選択行を開く
- [ ] 左ペインで `Home` を押すと「すべて」へ一発で戻る
- [ ] 左ペイン・右ペインで印字文字または修飾なしの `Backspace` を打つと検索ボックスへフォーカスが復帰する
- [ ] 左ペイン・右ペインで `Escape` を押すと検索ボックスへ戻る

*Escape の段階戻り(4段階)*
- [ ] Escape は1段階だけ戻る。順序は「左/右ペインにフォーカス → 検索ボックスへ戻る」「キーワードあり → キーワードをクリア」「スコープが『すべて』以外 → 『すべて』へ戻す」「いずれでもない → ポップアップを閉じる」

*編集モード*
- [ ] LIST / FOLDER_TREE / INLINE_EDIT / ALIAS_EDIT / DRAG / PANEL の各モードで ↑↓ / Enter / Escape の挙動が定義通りに切り替わる
- [ ] LISTモードで F2/Ctrl+E(リネーム)、Ctrl+;(別名編集)、Ctrl+M(移動)、Delete(削除)、Ctrl+D(現在ページ追加)が動作する

**優先度**: P0(必須)

#### 7. フォルダ移動(キーボード + ドラッグ&ドロップ)

**ユーザーストーリー**:
検索結果から整理したいユーザーとして、素早くフォルダを移し替えるために、キーボードとドラッグの両方で移動できる機能が欲しい

**受け入れ条件**:
- [ ] Ctrl+M でフォルダ選択パネルを開き、フォルダ名の絞り込み入力 → Enter で移動できる(キーボード代替は必須)
- [ ] 結果行全体をドラッグ可能(5px以上の移動で開始)、ゴースト表示、複数選択時は全件をまとめて運ぶ
- [ ] ドロップ先はフォルダのみ。現在の親フォルダはグレーアウトして無効化する
- [ ] 閉じたフォルダに600msホバーで自動展開(スプリングロード)、ペイン上下端40pxでオートスクロール、Escape/ペイン外ドロップで中止
- [ ] 移動は `chrome.bookmarks.move` を即時実行し、トーストで「[元に戻す]」を5秒間提供する
- [ ] 移動しても検索結果から消さず、フォルダパス表示だけ更新する
- [ ] フォルダ内の並び順変更はMVP対象外

**優先度**: P0(必須)

#### 8. 複数選択と一括操作

**ユーザーストーリー**:
まとめて整理したいユーザーとして、1件ずつ処理する手間を省くために、複数選択による一括移動・一括削除が欲しい

**受け入れ条件**:
- [ ] Ctrl/Cmd+クリックで個別追加、Shift+クリックで範囲選択、Ctrl/Cmd+Aで全件選択できる
- [ ] 通常はチェックボックス非表示(ファビコンのみ)、ホバー時にファビコン位置がチェックボックスに変化、1件以上選択中は全行で常時表示する
- [ ] 1件以上選択中はヘッダーが一括操作バー(「N件選択中 [移動] [削除] [選択解除]」)に切り替わる
- [ ] 一括操作のアンドゥは1単位として扱う(20件移動なら1回で全部戻る)

**優先度**: P0(必須)

#### 9. 現在のページをブックマーク登録

**ユーザーストーリー**:
今見ているページを保存したいユーザーとして、流れを止めずに登録するために、ポップアップ内で別名付きの即時登録ができてほしい

**受け入れ条件**:
- [ ] ヘッダー右の「+ 追加」で即座に登録し、続けて編集パネルを開く(登録済みなら「★ 登録済み」表示で編集パネルを開く)
- [ ] 編集パネルでタイトル編集・保存先フォルダ選択(絞り込み検索付きドロップダウン)・別名付与ができる
- [ ] 保存先フォルダの初期値は前回使用したフォルダとする
- [ ] パネル操作中にポップアップが閉じても登録は残る(即時登録してから編集)
- [ ] 各フィールドは変更のたびに即時保存し、[削除] で登録取り消し、[完了] でパネルを閉じる

**優先度**: P0(必須)

#### 10. ファビコン表示

**ユーザーストーリー**:
一覧を視覚的に把握したいユーザーとして、サイトを見分けやすくするために、ファビコン表示と未訪問サイト向けのフォールバックが欲しい

**受け入れ条件**:
- [ ] `favicon` 権限でファビコンを取得して表示する(外部通信なし)
- [ ] 取得失敗・未訪問サイトでは頭文字アバターにフォールバックする(ドメイン先頭1文字を大文字化、`www.` 等は除去)
- [ ] 頭文字アバターの背景色はドメインのハッシュから固定パレット(8〜12色)を選び、同一ドメインは常に同色にする
- [ ] ファビコンとアバターでサイズ・角丸を揃え、切り替わってもレイアウトが動かない

**優先度**: P0(必須)

#### 11. インポート / エクスポート(オプションページ)

**ユーザーストーリー**:
環境を移行するユーザーとして、別名を含む資産をそのまま持ち運ぶために、独自JSON形式のインポート/エクスポートが欲しい

**受け入れ条件**:
- [ ] ファイルダイアログでポップアップが閉じる制約のため、本機能はオプションページに配置する
- [ ] 標準HTML形式(Netscape Bookmark File)の入出力に対応する(インポートは新規作成のみのシンプル動作)
- [ ] 独自JSON形式(`format: "my-bookmark-search"`, `version`, `bookmarks[]`)で url / title / folderPath / aliases / addedAt を入出力する
- [ ] 独自JSONインポート時、URLをキーに突合し、存在しないフォルダは自動作成する
- [ ] 重複処理: 同一URLなし→新規作成+別名登録 / 別名のみ差分→別名マージ / タイトル・フォルダ相違→スキップ・上書き・両方残すをユーザー選択(一括適用可)
- [ ] `version` により将来のフォーマット変更後も旧ファイルを読める設計とする

**優先度**: P0(必須)

#### 12. ゴミ箱(削除データの保持・復元)

**ユーザーストーリー**:
誤削除を恐れるユーザーとして、後から取り戻せる安心のために、即時アンドゥとは別の30日保持のゴミ箱が欲しい

**受け入れ条件**:
- [ ] 即時アンドゥ(5秒・メモリ)とゴミ箱(30日・`storage.local`、期間は設定可)の2層構造で保持する
- [ ] 保存対象は URL・タイトル・元フォルダパス・別名・削除日時。フォルダ削除時は配下ツリーごと丸ごと保存する
- [ ] 復元は元のフォルダパスへ戻し、フォルダが存在しなければ自動再作成する(再作成で復元、ID・作成日時は変わる)
- [ ] 件数上限(例500件)または容量上限を設け、超過分は古いものから自動削除する
- [ ] ゴミ箱UIはオプションページの「ゴミ箱」タブに置く(ポップアップ側は即時アンドゥのみ)

**優先度**: P1(重要)

#### 13. ポップアップ状態の復元

**ユーザーストーリー**:
同じ作業を繰り返すユーザーとして、ポップアップを開き直すたびに操作をやり直さずに済むように、前回どこを見ていたかを引き継いでほしい

**受け入れ条件**:
- [ ] 以下の4項目を `chrome.storage.local`(端末固有)に保存し、次回起動時に復元する
  - フォーカス位置(検索ボックス / 右ペイン / 左ペイン)
  - フォルダスコープ(フォルダID)
  - 選択中のブックマーク
  - 検索クエリ
- [ ] **保存された状態がない初回起動時**は、フォーカス位置=**左ペイン(フォルダツリー)** / スコープ=**「すべて」** / 選択行=**先頭行** / クエリ=**空** とする
- [ ] 選択中のブックマークは**インデックスではなくブックマークID で保存する**(ブックマークの増減や検索結果の変化でズレないようにするため)
- [ ] **Chrome標準機能などで削除・変更され、保存先が見つからない場合は、当該項目のみ初回起動時と同じ既定値へフォールバックする**
  - 保存されたフォルダが存在しない → スコープを「すべて」へ
  - 保存されたブックマークが存在しない → 選択行を先頭行へ
  - フォーカス位置は影響を受けず、保存値のまま復元する
- [ ] 保存されたクエリで結果が0件になる場合もそのまま表示する(`Escape` の段階戻りで1段ずつ解除できる)
- [ ] 保存は**変更のたびに即時(debounce付き)** 行う。ポップアップは外側クリックで唐突に閉じるため、閉じる直前の一括保存には依存しない
- [ ] 復元されたクエリが残った状態で印字文字を打って検索ボックスへ復帰したときは、**既存クエリを全選択状態にして次の入力で置き換わる**ようにする(継続して絞り込む場合は `→` / `End` でキャレットを末尾へ送る)
- [ ] 復元の適用は検索索引の構築完了後に行う(選択行のID解決に検索結果が必要なため)。フォーカス位置は既定値を先に適用し、読み込み後に上書きする

**優先度**: P1(重要)

### キーボードショートカット一覧

#### フォーカス位置別

**検索ボックス**(起動直後のフォーカス位置)

```
文字入力           インクリメンタル検索
← →               キャレット移動(ペイン移動には使わない)
↑ ↓               フォーカスが外れ、同時に選択行が1つ移動
Enter              選択行を現在のタブで開く
Ctrl/Cmd + Enter   選択行を新しいタブで開く
Escape             1段階だけ戻る
```

**右ペイン(ブックマーク一覧)**

```
↑ ↓               選択行の移動(端では何もしない)
←                  左ペインへ
Enter              選択行を現在のタブで開く
Ctrl/Cmd + Enter   選択行を新しいタブで開く
印字文字 / Backspace 検索ボックスへ復帰
Escape             検索ボックスへ戻る
```

**左ペイン(フォルダツリー)**

```
↑ ↓               展開中のフォルダ間を移動(スコープが追従)
←                  親フォルダへ移動(最上位では何もしない)
→                  右ペインへ
Enter              展開 / 折りたたみのトグル
Home               「すべて」へ戻る
印字文字 / Backspace 検索ボックスへ復帰
Escape             検索ボックスへ戻る
```

#### 編集・整理(LISTモード)

```
F2 / Ctrl+E        リネーム(INLINE_EDIT へ)
Ctrl+;             別名編集(ALIAS_EDIT へ)
Ctrl+M             移動(フォルダ選択パネル)
Delete             削除(アンドゥ付き)
Ctrl+D             現在のページを追加
Ctrl/Cmd + クリック  個別選択の追加
Shift + クリック     範囲選択
Ctrl/Cmd + A        全件選択
```

#### Escape の段階戻り

```
1. 左/右ペインにフォーカス   → 検索ボックスへ戻る
2. キーワードあり            → キーワードをクリア
3. スコープが「すべて」以外   → 「すべて」へ戻す
4. いずれでもない            → ポップアップを閉じる
```

## 非機能要件

### パフォーマンス
- ポップアップ起動からフォーカスが確定し、キー操作を受け付けられるまで: 200ms以内(既定値のフォーカスを先に適用し、保存状態の復元は読み込み完了後に上書きする)
- インクリメンタル検索の1文字あたり再描画: 1,000件のブックマークで100ms以内
- 別名保存(upsert): 該当チャンクのみ書き込みで100ms以内
- 検索結果は仮想スクロール等で、件数増加に対しても描画コストを一定に保つ
- メモリ使用量・バンドルサイズの数値基準は architecture.md「パフォーマンス要件」に従う

### ユーザビリティ
- 新規ユーザーがインストール後、説明なしで検索・オープンの基本操作を1分以内に習得できる(初見ユーザー5名程度のタスク型ユーザビリティテストで検証)
- **すべての主要操作にキーボード手段が割り当てられ、マウスなしで完結できる**。クリックでしか到達できない操作を残さないことを設計上の必須条件とする(現時点の未達項目は「未確定の論点」を参照)
- 起動からブックマークを開くまで、マウスに持ち替えずに到達できる(起動ショートカット → 印字文字/Backspace で検索ボックスへ復帰 → 入力 → `↑↓` → `Enter`)
- 「なぜヒットしたか」(マッチした別名)を必ず可視化し、別名機能の価値を体感させる
- 破壊的操作(削除・移動)は必ずアンドゥ手段を伴い、**そのアンドゥ手段自体もキーボードで発動できる**

### 信頼性
- 削除・移動を含む全操作でデータ損失ゼロ(即時アンドゥ + 30日ゴミ箱の二重防御)
- ブックマークIDではなくURLハッシュで別名を紐付けることで、別名がブックマークIDの変化に影響されない。これにより:
  - **同一Googleアカウントの端末間**: `chrome.storage.sync` の自動同期で別名が保持される(前提: サインイン・同期有効)
  - **別アカウント・別プロファイルへの移行**: 独自JSONのエクスポート/インポート(手動)で別名を引き継ぐ
- `chrome.storage.sync` の容量上限(8KB/アイテム、512アイテム)を超えた際は `storage.local` に自動フォールバックする
- 存在しなくなったフォルダID・別名参照は起動時に掃除する

### セキュリティ / プライバシー
- 外部通信を完全にゼロとし、host permission を要求しない
- 権限は `bookmarks` / `storage` / `activeTab` / `favicon` の4つのみ
- 「データ収集なし」をプライバシーポリシーで明示し、技術的にも保証する
- `favicon` 権限の警告表示有無を申請前に現行ドキュメントで確認する

### スケーラビリティ
- 別名データは100件ずつのチャンクを1キーにまとめて保存し(`alias_chunk_0`...)、512アイテム制限による破綻を回避する
- ブックマーク数千件規模でも検索・表示のパフォーマンス要件を満たす

### 互換性 / 国際化
- Manifest V3 準拠
- `_locales` による多言語対応(日本語 / 英語)を行い、デフォルトロケールは日本語(ja)とする

## スコープ外

明示的にMVPスコープ外とする項目:
- ローマ字→かな自動変換、漢字読み推定(辞書同梱による肥大化を避ける)
- frecencyソート、タグ機能
- リンク切れ検出、重複ブックマーク検出
- オムニボックス連携、サイドパネル対応
- フォルダ内の並び順変更
- テレメトリによる利用状況の自動計測(外部通信ゼロの方針による)

## 未確定の論点(継続検討)

1. **複数選択の詳細仕様**: 選択状態の永続性、検索語変更時の選択解除の扱い、一括操作時の確認ダイアログの要否
2. **独自JSONにゴミ箱データを含めるか**: 含めればエクスポートで持ち出せるが、ファイルサイズが増える
3. **編集UIの展開アニメーション**: 行が2段から4段に伸びる際の挙動
4. **フォルダペインの幅変更**: ユーザーがドラッグでリサイズできるようにするか

### キーボード手段が未定義の操作(「マウスなしで完結」の未達項目)

機能5・機能6 の見直し([ideas/keyboard-first-navigation.md](./ideas/keyboard-first-navigation.md))でフォルダスコープのキーボード操作は解決したが、以下は依然クリックでしか到達できない。非機能要件「マウスなしで完結できる」を満たすには別途対応が必要。

| # | 操作 | 現状の唯一の手段 | 該当機能 |
|---|------|-----------------|---------|
| 1 | **アンドゥ** | トーストの `[元に戻す]` クリックのみ(`Ctrl+Z` 未定義) | 機能4/7/8 |
| 2 | **複数選択の個別追加・範囲選択** | `Ctrl/Cmd+クリック`・`Shift+クリック`(キーボードは `Ctrl/Cmd+A` の全選択のみ) | 機能8 |
| 3 | **一括操作バーの[移動][削除][選択解除]** | ボタンクリック | 機能8 |
| 4 | **別名チップの個別選択・削除・再編集** | クリック(`Backspace` は直前1個のみ) | 機能3 |
| 5 | インライン編集のタイトル⇄URL 間移動 | 未定義。「フォーカスアウトで確定」はマウス前提の記述 | 機能4 |
| 6 | 現在ページ登録パネル内(フォルダ選択・[削除]・[完了]) | クリック | 機能9 |
| 7 | オプションページを開く / ゴミ箱の復元操作 | クリック | 機能11/12 |
| 8 | ショートカット一覧の表示(`?`) | 存在しない | — |

> **#1 のアンドゥは優先度が高い**。破壊的操作の安全網がクリックでしか発動できず、利便性ではなく信頼性要件(「削除・移動を含む全操作でデータ損失ゼロ」)に関わる。

### 起動ショートカットの割り当て

`commands._execute_action` の `suggested_key`(`Ctrl+Shift+F` / mac `Command+Shift+F`)は、**他拡張が先に取得しているとインストール時に未割り当てのまま**になる。キーボード完結を掲げる以上「起動キーが効かない」は致命的なため、初回起動時に `chrome://extensions/shortcuts` への案内が必要。ただし拡張からこのURLは直接開けないため、コピー可能なテキストで示す方式を検討する。
