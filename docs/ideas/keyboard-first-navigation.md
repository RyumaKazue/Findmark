## 背景と目的

「クリックを使わずキーボードだけでブックマーク選択まで到達できる」ことを目標に、操作仕様を見直した。

調査の結果、**理想として挙げられた導線自体は既に成立していた**（以下は壁打ち時点＝仕様変更前の状態。起動時フォーカスはその後、左ペイン既定＋状態復元へ変更した。後述「フォーカスは3状態」を参照）。

```
Ctrl+Shift+F(manifest の _execute_action で定義済み)
  → 起動時に検索ボックスへ自動フォーカス
  → 入力でインクリメンタル検索
  → ↑↓ で選択
  → Enter で開く
```

一方で、**フォルダ絞り込み(PRD機能5)がクリック専用**という穴があった。機能5の受け入れ条件は全文が「左ペインのフォルダを**クリック**すると」「別フォルダ**クリック**で置き換え」「チップ**クリック**で直下のみトグル」で構成され、キーボード手段が1つも定義されていない。実装(`FolderTreeItem.tsx`)も `<button onClick>` のみ。

また、PRD「非機能要件 > ユーザビリティ」には既に **「すべての主要操作にキーボードショートカットが割り当てられ、マウスなしで完結できる」** と書かれている。つまり本変更は新しい野心の追加ではなく、**既に宣言済みの非機能要件に機能要件を追いつかせる作業**である。

## 確定仕様

### フォーカスは3状態

起動時は**既定で左ペイン(フォルダツリー)**。ただし保存された状態があればそれを復元する(2026-07-28 追加決定。PRD 機能13「ポップアップ状態の復元」/ 作業単位 U19)。`↑↓` で検索ボックスを抜け、印字文字または `Escape` で戻る。

> **起動時フォーカスの決定経緯**: 当初は「起動直後は検索ボックス」としていたが、フォルダから始めた方が便利という判断で既定を左ペインへ変更した。あわせて、フォーカス位置・フォルダスコープ・選択ブックマーク・検索クエリの4項目を次回起動時に引き継ぐこととした。「左ペイン」はあくまで**保存状態がない初回起動時のフォールバック**であり、固定の起動挙動ではない。印字文字で検索ボックスへ復帰できるため、「起動 → いきなり打ち始める」導線は維持される。

**選択行は常に存在する。** 検索ボックスにフォーカスがあっても右ペインには選択行があり(既定は先頭)、ハイライトされている。design の 1c 状態(先頭行を `#FAFBFF` で最有力表示)がこれに対応する。

#### 検索ボックス

| キー | 挙動 |
|---|---|
| 文字入力 | インクリメンタル検索 |
| `←→` | キャレット移動のみ(ペイン移動しない) |
| `↑↓` | **検索欄からフォーカスが外れ、同時に選択行が1つ移動する** |
| `Enter` | 選択行を現在タブで開く |
| `Ctrl/Cmd+Enter` | 選択行を新規タブで開く |
| `Escape` | 段階戻り(後述) |

#### 右ペイン(ブックマーク一覧)

| キー | 挙動 |
|---|---|
| `↑↓` | 選択行の移動(端では何もしない) |
| `←` | 左ペインへ |
| `Enter` | 選択行を現在タブで開く |
| `Ctrl/Cmd+Enter` | 選択行を新規タブで開く |
| 印字文字 | 検索ボックスへ復帰 |
| `Escape` | 検索ボックスへ戻る |

#### 左ペイン(フォルダツリー)

| キー | 挙動 |
|---|---|
| `↑↓` | 展開中のフォルダ間を移動(**移動と同時に右ペインが追従する**) |
| `←` | 親フォルダへ移動(最上位では何もしない) |
| `→` | 右ペインへ |
| `Enter` | 展開 / 折りたたみのトグル |
| `Home` | 「すべて」へ一発で戻る |
| 印字文字 | 検索ボックスへ復帰 |
| `Escape` | 検索ボックスへ戻る |

### 検索ボックスへ戻る手段

**印字文字を打つ**(検索ファースト復帰)と **`Escape`** の2つ。

> 検討段階で「右ペインの先頭行で `↑` → 検索ボックスへ戻る」案があったが**不採用**。検索ボックスで `↑`(選択が先頭)→ フォーカスが外れる、右ペインで `↑` → 検索ボックスへ戻る、となり同じキーで往復して落ち着かないため。

### スコープ(右ペインの内容)

- 常にどれか1つのフォルダにスコープがあり、起動直後は「すべて」
- **「すべて」のみ例外**: 全ブックマークを表示。検索時も全件が対象。並び順はクエリ空時**タイトル昇順**(現行の U6 実装を維持。デザインの「最近順」は非採用項目 #2 のとおり将来検討)
- **それ以外**: そのフォルダの**直下のブックマークのみ**。ブラウズ時(クエリ空)も検索時(クエリあり)も同じ
- 「サブフォルダを含む」トグルは廃止

> **深いフォルダでヒット0になる問題について**: 直下のみを厳格に適用すると、目的のフォルダに辿り着かない限り検索がヒットしない。これは「すべて」に戻ってから検索する運用で解決する。そのため**「すべて」へ素早く戻る手段が前提**となり、`Escape` の段階戻りと左ペインの `Home` がその役割を担う。

### Escape の段階戻り(4段階へ拡張)

フォーカス状態が増えたぶん、PRD機能6 の3段階を4段階に拡張する。

```
1. 左/右ペインにフォーカス  → 検索ボックスへ戻る
2. キーワードあり           → キーワードをクリア
3. スコープが「すべて」以外  → 「すべて」へ戻す
4. いずれでもない           → ポップアップを閉じる
```

深いフォルダでヒット0だったとき、`Escape` を2〜3回押せば全体検索に戻れる。

### フォルダチップ

機能5 の「フォルダをクリックすると検索ボックス先頭にチップが挿入される」「チップの `×` で解除」「チップクリックで直下トグル」は、**左ペインのフォーカスがスコープを決める**新方式と二重管理になる。

- チップは **「今どこを見ているか」のスコープ可視化**として残す(左ペインを深くスクロールしている時に有用)
- 挿入 / 解除 / 直下トグルという**操作の主体からは外す**
- design の 1b 状態はこの解釈でそのまま使える

## 解釈で埋めた点

壁打ちで明示的な回答がなかったため、合理的な解釈として仕様に入れた項目。**異論があれば再検討する。**

1. **左ペインで印字文字を打ったときの挙動** — 検索ボックスへ復帰(現行の検索ファースト復帰ルールを維持)。フォルダ名の頭文字ジャンプ(type-ahead)にする案もあったが、`←` で親へ戻れる以上、必要性が高くない。
2. **`Home` キーで「すべて」へ** — 「すべて」への高速復帰手段として追加。`Escape` の段階戻りでも到達できるが、深い階層からの一発復帰用。

### 追加決定(U8a実装中・2026-07-28)

- **検索ファースト復帰のトリガーに `Backspace` を追加**: 印字文字に加え、修飾なしの `Backspace` を左ペイン・右ペインからの検索ボックス復帰トリガーとした。「残っているクエリを消したい」という操作意図でも検索ボックスへ戻れるようにするため。既存の印字文字復帰と同じ仕組み(ブラウザの既定動作が、キーイベント処理中に同期的にフォーカス移動した先の要素に対して適用される挙動)に乗せて実装し、`query` を明示的に書き換える処理は追加していない。`modeMachine.ts` に `isSearchFirstTriggerKey`(`isPrintableKey` を内包)として実装。
- **マウス操作(📎ボタン等)と内部フォーカスモデルの不整合、および根本解決(2026-07-28)**: U8a はキーボード駆動のフォーカスモデル(`listFocus`/`mode`)のみを管理し、マウスでネイティブ `<button>`(📎・結果行・展開三角)をクリックした際の実DOMフォーカスの変化とは同期させていない。このため、📎クリック後に矢印キーで移動しても、実際のDOMフォーカスが検索ボックスに残ったままになりうる(見た目のフォーカスリングと内部モデルの食い違い)。機能的には内部モデルに従って正しく動作するため実害は小さいが、視覚的には紛らわしい。`FolderTree.tsx`/`ResultRow.tsx` はU8aの対象領域外であり、根本対応にはこれらへの変更が要るため、**U8aでは対応せずU11に持ち越す**方針とした。

  その後、この問題自体を構造的に解消する **U11 のマウス操作再設計**が決定した。現在フォルダ行は「三角+📁+フォルダ名」全体が1つの押下対象で展開/折りたたみを行い、選択(スコープ変更)は右端の📎ボタンが別途担っている。これを**2つの押下対象に分離**する:
  1. **展開三角のみ** → 展開/折りたたみ専用。現在の記号(`▸`/`▾`)は単体では直感的でないため、わかりやすい見た目に変更する(具体案はU11計画時に決定)。
  2. **「📁 フォルダ名」の名前部分** → そのフォルダをスコープにする(現在の📎の役割を引き継ぐ)。子を持たないフォルダも常に押下可能にする(現状は非ボタンの `<span>` で選択不可のため変更が必要)。

  この再設計により**📎ボタンは撤去**する。マウスクリックが直接スコープ変更(=キーボードのフォーカス移動と同じ状態更新経路)を担うようになるため、「マウス操作と内部フォーカスモデルの不一致」という問題自体が発生しなくなる。

## 未解決の穴(本変更のスコープ外・今後の検討課題)

## 記録に残す制約・検討材料

### Chrome 拡張ポップアップ固有の制約

仕様策定時に考慮すべき事項として記録する。

- `Ctrl+T` / `Ctrl+W` / `Ctrl+N` などブラウザ予約キーはポップアップ内で奪えない。割り当て候補から除外が必要
- `suggested_key`(現在 `Ctrl+Shift+F` / mac `Command+Shift+F`)は、**他拡張が先に取っているとインストール時に未割り当てのまま**になる。キーボード完結を掲げる以上「起動キーが効かない」は致命的なので、初回起動時に `chrome://extensions/shortcuts` への案内が要る。ただし拡張からこのURLは直接開けないため、コピー可能なテキストで示す必要がある
- ファイルダイアログを開くとポップアップが閉じる。既知の制約で、インポート/エクスポート(機能11)をオプションページへ逃がすことで対応済み

### 検討したが不採用にした案

| 案 | 不採用の理由 |
|---|---|
| フォーカスモデルを Tab 循環型にする | 「文字を打つと検索に戻る」検索ファーストのルールと Tab 移動が競合する |
| ペイン移動を `Tab`/`Shift+Tab` に割り当てる | 「左右矢印で移動」という方針から外れる |
| 検索ボックスで「キャレットが端にあるときだけ `←→` で抜ける」 | `↑↓` を抜けるキーにする案で衝突が原理的に消えたため不要になった |
| 検索ボックスが空のときだけ `←→` でペイン移動 | 同上 |
| 左ペインで「行き止まりなら `→` で抜ける」標準ツリー方式 | `←→` の意味を常に一定にする方針を優先 |
| 親フォルダへ戻るのを `Backspace` に割り当て | 左ペインの `←` が空いていたため不要になった |
| 検索ボックス内でのフォルダ名プレフィックス補完(`>開発/chr` → Tab) | 左ペインのキーボード操作で足りるため見送り。将来の高速化案として記録 |
| オムニボックス連携(`Ctrl+L` → `fm ` → キーワード)を MVP へ格上げ | 判断未了。Post-MVP(P2)のまま。キーボード完結の最短経路ではあるが、`omnibox` 権限の追加・候補描画の別実装(ファビコン/別名チップを出せない)・MVP肥大化のコストがある |
