# ブランチ作成

引数で渡されたブランチ名で、**ブランチ戦略に基づいた親ブランチから**新しいブランチを切ります。

引数: **ブランチ名(必須)**。プレフィックス付きの完全な名前を推奨(例: `feature/alias-editor`)。

```bash
> /create-branch feature/alias-editor
> /create-branch fix/favicon-fallback
> /create-branch chore/update-manifest
```

---

## ブランチ戦略(親ブランチの決定ルール)

`docs/development-guidelines.md` の「ブランチ戦略」に準拠する。運用は `feature/* → dev → main` の2段階フロー。

- **すべての作業ブランチ(`feature/*` `fix/*` `refactor/*` `chore/*`)は `dev` から分岐する。**
- したがって、このコマンドの**親ブランチは原則 `dev`** とする。
- `main` / `dev` へは直接コミットしない。

**プレフィックスの目安(引数がプレフィックス無しの場合の判断材料):**
- `feature/[機能名]`: 新機能
- `fix/[修正内容]`: バグ修正
- `refactor/[対象]`: リファクタリング
- `chore/[内容]`: 設定・ドキュメント等

---

## 実行手順

### ステップ1: 引数の検証

1. ブランチ名(第1引数)を取得する。**未指定の場合はエラーとし、ブランチ名を求めて停止する。**
2. ブランチ名にプレフィックス(`feature/` `fix/` `refactor/` `chore/`)が付いているか確認する。
  - 付いていない場合: 変更内容から適切なプレフィックスを推定してユーザーに提案し、確認を得てから採用する(勝手に確定しない)。
3. `git branch --list <ブランチ名>` で同名ブランチが既に存在しないか確認する。存在する場合はエラーとして停止する。

### ステップ2: 親ブランチの決定

1. 親ブランチを `dev` に設定する(ブランチ戦略に基づく)。
2. `dev` の存在を確認する:
  ```bash
  git fetch origin --prune
  git rev-parse --verify dev              # ローカルの dev
  git ls-remote --heads origin dev        # リモートの dev
  ```
3. 存在状況に応じて分岐する:
  - **ローカルに `dev` あり:** そのまま親ブランチとして使用。
  - **ローカルに無く、リモート `origin/dev` あり:** `origin/dev` を親ブランチとして使用(ステップ3で追跡ブランチとして作成)。
  - **どこにも `dev` が無い:** ブランチ戦略上の親 `dev` が未整備。**ここで停止し**、ユーザーに次を確認する:
    - `dev` を `main` から新規作成して、それを親にするか。
    - または、今回に限り `main` を親にするか。
    - ユーザーの指示なしに `main` を親として進めない。

### ステップ3: ブランチの作成

1. 親ブランチを最新化する:
  ```bash
  git fetch origin --prune
  ```
2. 親ブランチ(`dev` または合意した代替)から、指定名でブランチを切って切り替える:
  ```bash
  # ローカル dev から
  git switch -c <ブランチ名> dev

  # または origin/dev から(ローカル dev が無い場合)
  git switch -c <ブランチ名> origin/dev
  ```
3. 作成後、以下を報告する:
  - 作成したブランチ名
  - 親ブランチ(と、その参照元 local/remote)
  - 現在チェックアウト中であること

### ステップ4: 完了報告

- 作成したブランチと親ブランチを明示する。
- リモートへの push は**このコマンドでは行わない**(初回コミット時、または `/commit-steering` 等に委ねる)。
- ワーキングツリーに未コミットの変更があった場合は、その旨と、新ブランチへ持ち越された事実を報告する。

---

## 注意事項

- `main` / `dev` を作業ブランチとして直接使わない。必ず本コマンドで分岐する。
- 親ブランチは常にブランチ戦略(`dev`)に従う。特別な理由がある場合のみ、ユーザーの承認を得て変更する。
